# PetBox

Self-hosted **модульный монолит** (.NET 10), который даёт ИИ-агентам для разработки постоянную инфраструктуру.

- **Что это:** история рабочих сессий, долговременная память с поиском, доски задач с настраиваемой
  методологией, отказоустойчивый LLM-роутер и MCP-поверхность над всем этим.
- **Дополнительно:** конфигурация на тегах, приём логов с KQL-движком, SQLite-базы по проектам,
  дашборд здоровья и CI, учёт деплоев. Каждая подсистема включается флагом.
- **Разрабатывается на самом себе:** план, спецификация и задачи живут на досках PetBox и доступны по MCP.

Живой инстанс: <https://petbox.3po.su>

## Агентская часть

### Сессии и дайджесты

- **Что:** агенты дописывают транскрипты рабочих сессий; эпизодический поиск находит прошлые решения.
- **Как:** фоновая задача (`SessionDigestJob`) сжимает транскрипты в дайджесты.

### Поиск по памяти

- **Что:** гибридный поиск по записям памяти.
- **Как:**
  - лексический ранг даёт SQLite **FTS5**, семантический ранг - эмбеддинги;
  - оба списка сливаются через **Reciprocal Rank Fusion** (`PetBox.Core/Search/HybridMerge.cs`);
  - необязательный LLM-**реранкер** переупорядочивает результат.
- **Почему так:** RRF-оценка зависит только от ранга, поэтому сопоставима между хранилищами.
  Несколько контейнеров памяти сливаются глобально, а не по очереди.

### Темпоральная память и дедупликация фактов

- **Темпоральность:** запись не перезаписывается. У каждого ключа хранится история ревизий, а
  частичный уникальный индекс гарантирует не более одной *активной* ревизии на ключ. Удалять
  безопасно: история остаётся.
- **Дедупликация:** автоматически собранные факты сравниваются с существующими сначала по
  нормализованному тексту, затем по косинусной близости эмбеддингов (порог по умолчанию 0.92).

### Наблюдения (observations)

- **Что:** встроенная доска в каждом проекте для находок типа «что-то сломано».
- **Как:**
  - при создании запись проверяется по нормализованному тексту, затем по косинусной близости
    title+body (порог 0.75);
  - при совпадении растёт счётчик повторений, дубль не создаётся;
  - наблюдение в статусе `seen` можно *повысить* (promote) до задачи или идеи. Когда задача
    доходит до успешного терминального статуса, наблюдение переходит в `fixed`; повторное
    появление проблемы снова его открывает.

### Отказоустойчивый LLM-роутер

- **Что:** chat / embed / rerank за одним фасадом (`PetBox.LlmRouter`), для каждой возможности
  упорядоченная цепочка fallback.
- **Как circuit breaker ограничивает сбой, по классу:**
  - хост недоступен: открывается весь endpoint, для всех возможностей;
  - 429 или 5xx: открывается только звено этого endpoint для одной возможности.
- **Почему:** на продакшене было измерено, что лимит запросов на Chat молча уводил трафик Embed и
  Rerank на запасной маршрут. Открытие breaker логируется один раз на переход, а не на каждый
  пропущенный запрос.

### MCP-поверхность

Более 100 тулов (методы `[McpServerTool]` в `src/PetBox.Web/Mcp`): задачи, память, сессии,
комментарии, связи, конфиг, логи, данные, LLM, деплой. Агенту отдают не все сразу.

**Обнаружение**
- `tools/list` показывает ключу только те тулы, на которые у него есть scope, причём по каждому
  тулу отдельно: без `tasks:write` тул `tasks_upsert` не виден.
- `whoami` возвращает все модули, их scope с признаком `granted` и имена всех тулов, чтобы агент
  отличал «недоступно этому ключу» от «не существует».
- `tool_describe` описывает любой тул по имени.

**Scope**
- Каждый тул объявляет нужный scope один раз. Эту единственную декларацию читают call-gate,
  `tools/list` и `whoami`.
- API-ключ несёт перечисляемый набор scope и project claim (возможен wildcard `*`).

**Безопасность**
- Скрытие - не граница: вызов без нужного scope отклоняется независимо от видимости.
- Тест роняет сборку, если у тула нет декларации.
- Sandbox-only ключи отвергаются на проектах без флага sandbox.

### Движок методологии

- **Что:** доски следуют пользовательской методологии (у нас idea -> spec -> work -> intake).
- **Как:** переходы статусов и гварды обеспечивает движок (`PetBox.Tasks.Engine`).
- **Подробнее:** [doc/methodology.md](doc/methodology.md), [doc/methodology-engine.md](doc/methodology-engine.md).

## Модули

| Проект | Назначение |
|---|---|
| `PetBox.Core` | аутентификация, модели, SQLite-контекст и миграции, поиск (FTS, hybrid merge, rerank), feature toggles |
| `PetBox.Web` | единая точка входа: Program.cs, Razor Pages, фронтенд, MCP-эндпоинт |
| `PetBox.Tasks` / `PetBox.Tasks.Engine` | доски задач, движок методологии |
| `PetBox.Memory` | темпоральные хранилища памяти, гибридный поиск |
| `PetBox.Sessions` | транскрипты, дайджесты, эпизодический поиск |
| `PetBox.LlmRouter` (+ `.Contract`) | маршрутизируемые chat / embed / rerank |
| `PetBox.Config` | конфигурация на тегах, детерминированный resolve |
| `PetBox.Log.Core` | приём логов (Seq-совместимый и OTLP), KQL-движок |
| `PetBox.Data` | SQLite-базы по проектам, raw-SQL REST, миграция схем |
| `PetBox.Dashboard`, `PetBox.Deploy` | опрос здоровья и CI, учёт деплоев |

- Клиентские SDK (.NET, TypeScript, Python): `src/clients-net`, `src/clients-ts`, `src/clients-py`.
- Каждая подсистема включается флагом `Features:<Name>`; выключенная ничего не стоит в рантайме.

## Стек

- **Бэкенд:** .NET 10, SQLite через linq2db, FluentMigrator, Kusto.Language + KustoLoco (KQL), OpenTelemetry.
- **Фронтенд:** Razor Pages (SSR), htmx 2, Alpine.js 3, Tailwind 3 + daisyUI 4, TypeScript через bun.
- **Поставка:** Docker (chiseled noble runtime), Cake + GitVersion, GitHub Actions, Playwright для E2E.

## Сборка и запуск

Нужны: .NET SDK 10 (см. `global.json`), bun, PowerShell или bash.

```sh
./build.ps1 -Target Test        # или: ./build.sh --target=Test
./build.ps1 -Target Dev         # watcher'ы bun + `dotnet watch run` из src/PetBox.Web
./build.ps1 -Target Verify      # Test + lint/typecheck/тесты клиентских SDK
```

- Остальные цели в `build.cs`: `Docker`, `DockerSmoke`, `DockerPush`, упаковка и публикация SDK.
- Контейнер слушает порт 8080, данные хранит в `/app/data`.

## Инженерные практики

### Единый гейт

- Цель Cake `Test` - единственное определение «зелёного»: сборка, проверка форматирования, lint и
  unit-тесты фронтенда, затем .NET-тесты (более 4000 тест-кейсов).
- CI запускает ту же цель, поэтому зелёный локальный прогон не может быть красным в пайплайне.

### Архитектура как тесты

- Тесты границ для каждого модуля.
- `DataConnection` нельзя получить через DI (он не потокобезопасен); к базе обращаются только из
  сервисного слоя.
- Проверки кросс-тенантной авторизации; ratchet, требующий декларацию scope у каждого MCP-тула.
- Где: `tests/PetBox.Tests/Architecture`.

### CI/CD

- Тесты идут на каждый push в `main`.
- Тег `deploy` запускает тесты, публикацию образа в ghcr, SSH-деплой и health-check после него.
- Гейт `jb inspectcode` блокирует деплой на помеченном коммите; SDK публикуются по своим тегам.

### Процесс

- Любое изменение начинается с карточки на досках PetBox, делается в git worktree и заканчивается
  запушенной веткой. Правила: [AGENTS.md](AGENTS.md).
