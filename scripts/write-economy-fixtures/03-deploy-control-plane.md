## Проблема

PetBox доводит проекты до рабочего состояния за минуты, и узким местом стал **деплой, мониторинг и управление** растущим числом проектов. Все нагрузки — docker-контейнеры, получающие на вход URL + ключ PetBox + тег-вектор; машины слабые и разнородные (1–2 ГБ RAM), с разными сетевыми ограничениями (где-то заблокирован x.com, где-то нужен kino.pub) и разными дисками (NVMe vs HDD). Сейчас каждый проект тащит копипастом свой deploy-шаг в GitHub Actions (хост/логин/пароль/сертификат в секретах репы) — это утечка инфра-ответственности в пайплайн каждого продукта.

## Модель

**PetBox — control plane** (мозг: реестр узлов, желаемое состояние, UI, отображение «ключ+тег-вектор → параметры контейнера»). На каждой машине — **тонкий pull-агент** (руки: цикл сверки желаемого с фактическим). PetBox тут особенный — он платформа, а другие проекты — потребители.

**Pull-only**: агент только исходящим HTTPS опрашивает PetBox, входящих портов нет → проходит сквозь NAT и сетевые ограничения, безопаснее, делает локальный ПК (через WSL2) бесплатной нодой. Это совпадает с тем, как контейнеры уже работают (сами идут к PetBox).

## Хотелки (закрываются desired-state + reconcile)

1. Перемещать сервис по серверам — сменить node у записи деплоя.
2. Копии на разных серверах — сервис = N записей.
3. Старт/стоп вообще или на конкретной ноде через UI — тумблер desired.
4. Локальный ПК как нода — тот же агент в WSL2.
5. Запуск контейнера с параметрами из ключа+вектора — содержимое записи деплоя.

## Scope v1 (зафиксировано)

**Ядро + авто-перенос (failover):** реестр нод, desired-state, reconcile (start/stop/move/copy), heartbeat, UI-грид, **и** авто-перенос relocatable-сервисов при смерти ноды.

ВНЕ v1: canary-by-node, RAM-aware скоринг размещения, упрощение CI потребителей.

## Решения

- Модуль **PetBox.Deploy**, MCP-поверхность `deploy.*`.
- Хранение desired-state — **отдельные таблицы** (новый DeployDb: node + deployment); env/параметры по-прежнему через `/v1/conf`.
- Агент — **Python** MVP (systemd на Ubuntu, ~0 ресурсов).
- rolling/canary/mesh не делаем (топология «звезда», слабая RAM); единственный триггер «пора на Nomad» — bin-packing под давлением.
- Авто-перенос: режим отказа — двойной запуск, не потеря данных; гейтится флагом relocatable; старый агент самогасится при возврате.
