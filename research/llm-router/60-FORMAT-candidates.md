# Этап 2: «убить модуль?» — формат карточки кандидата (файлы 61-, 62-, 63-)

Вопрос владельца: модуль LlmRouter требует убийства? Нужна аналитика самых сильных и лёгких
аналогов, которые закроют (A) текущие потребности сервера PetBox, (B) локальные хотелки про codex,
(C) потребности проекта archive. Ответ «убить / оставить тонкий слой / оставить» — выводится из матрицы.

## Требования (id для матрицы)
Сервер PetBox (сегодня, см. 10/11/20):
- S1 chat OpenAI `/v1/chat/completions`, `response_format` (json_schema), thinking on/off
- S2 embeddings `/v1/embeddings`
- S3 rerank `/v1/rerank` (Cohere/Jina-стиль), в т.ч. на llama-server
- S4 цепочка fallback дом→облако по capability/tier, circuit breaker, Retry-After
- S5 домашний эндпоинт: self-signed TLS / пиннинг сертификата или свой CA
- S6 инвариант пространства эмбеддингов: embed-fallback только между моделями одного пространства (EmbedSpaceId); rerank: весь запрос (все чанки) на одной модели
- S7 мульти-тенантность: ключи на проект, уровни конфигурации project/workspace/system, бюджеты/лимиты на ключ
- S8 учёт usage/стоимости, логи запросов (желательно OTLP/структурные)
- S9 управление конфигом через API (чтобы MCP `llm_config_*` PetBox стал тонкой обёрткой) и hot reload
- S10 ресурсы: рядом с PetBox в docker на одном VPS — RAM idle/под нагрузкой, внешние зависимости (Postgres/Redis?) — чем меньше, тем лучше
Codex / локальные машины:
- X1 вход OpenAI Responses API (`/v1/responses`, стриминг SSE, tool calls) — codex умеет только его
- X2 трансляция Responses → chat completions к апстримам без Responses (DeepSeek, GLM, llama-server) с корректным стримингом и tool calls
- X3 маршрутизация по имени модели в теле (виртуальные имена → провайдер+модель)
- X4 бесплатные модели с автоотвалом: квота исчерпана → долгий cooldown, переход на платное
- X5 переписывание заголовков (удалить/добавить/подставить ключ) на маршрут/провайдера
- X6 вход Anthropic `/v1/messages` (opencode-go MiniMax/Qwen, Claude Code) — nice
- X7 автономно: один бинарник/служба Windows (+systemd), конфиг из файла, без PetBox и без БД
- X8 сохранение кеша промптов: sticky провайдер на сессию
Archive:
- A1 vision content-parts (image_url/base64) в chat
- A2 мультимодальный embed (картинка+текст в одном пространстве)
- A3 embed/rerank по REST

## Формат файла кандидата
Для каждого кандидата раздел:
- Кратко: язык/рантайм, лицензия (и что за paywall/enterprise), активность (последний релиз/коммит, дата), звёзды.
- Лёгкость: размер бинаря/образа, RAM idle (цифра + источник или «не нашёл»), обязательные зависимости (БД, Redis), способ запуска (бинарь/служба/docker).
- Матрица: таблица `id | ✅/⚠️/❌/? | как именно (ключ конфига, эндпоинт) | источник URL`. Для ⚠️ — в чём ограничение. «?» честнее, чем догадка.
- Модель отказоустойчивости: что у него вместо нашего автомата (cooldown, allowed_fails, breaker, классы ошибок, Retry-After, долгий cooldown по квоте).
- Пример конфига под наш кейс (codex X1–X4 + сервер S2/S3/S4), ≤30 строк, если реально выводится из доков.
- Вердикт: закрывает A / B / C полностью/частично, главная дыра.
Лимит на файл 300 строк. Все утверждения — с URL (docs, README, исходник). Сеть: при блокировке `pfetch --text <url>` (Git Bash), github → raw.githubusercontent.com; никогда не печатать креды из ~/.pfetch.conf.
В чат-ответе содержимое не повторять — 5–8 строк итога.
