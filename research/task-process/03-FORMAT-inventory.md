# ФОРМАТ инвентаря направления — читать ПЕРВЫМ

Дата: 2026-09-25. Обязателен для `11-*`…`18-*`. Если формат мешает — скажи в §9, не меняй молча.
Лимит: **≤160 строк**. Язык: русский, термины кода — как в коде.

## Жёсткие правила

- PetBox (проект `$system`) — **только чтение**. Никаких `tasks_upsert`, `comments_upsert`,
  `memory_*` записей, наблюдений, `session_*` записей. Найденный дефект — впиши в §8, не заводи.
- Пишешь **только свой файл**. Чужие файлы не трогаешь.
- Код/доки проверяй по `origin/main` (`git grep <pat> origin/main`, `git show origin/main:<path>`),
  не по рабочему дереву основного чекаута.
- Каждый факт — с источником. Узел: `board/key` + статус + permalink (`includeUrl:true`).
  Сессия: id + дата + цитата ≤2 строк. Код: `path:line`. Нет источника — пометь `[гипотеза]`.
- Ищи во ВСЕХ статусах, включая терминальные: закрытое/отклонённое — тоже данные.
- Кириллица в JSON вызовов — сырой UTF-8, никаких `\uXXXX`.
- В ответе оркестратору **не пересказывай файл**: ≤8 строк — путь, 3 главных вывода,
  1 главное несогласие с формулировкой владельца (если есть).
- Несогласие с владельцем — ценный выход, а не грубость. Если формулировка D# неверна
  фактически или предлагаемое решение хуже альтернативы — скажи прямо в §7.

## Разделы

```
# D# <название> — инвентарь
Дата, автор (модель, которой ты РЕАЛЬНО работаешь), источники просмотрены: <кол-во узлов/сессий/файлов>

## 1. Суть проблемы одним абзацем (своими словами, после изучения)
## 2. Доказательства
   2a. Карточки (ideas/spec/work/intake) — таблица: узел | статус | одна строка сути
   2b. Наблюдения (observations)
   2c. Сессии (session_search) — id, дата, цитата
   2d. Память (memory_search) / канон / скиллы / доки / код
## 3. Что уже сделано или решено раньше (включая research/*) — и проверено ли, что это живо
## 4. Механизм: почему так происходит (факт / [гипотеза] — помечать)
## 5. Как принято в индустрии (≤10 строк; только если есть что сказать по делу)
## 6. Варианты решения — для каждого: суть | цена | что ломается / риск
## 7. Несогласия и сомнения в постановке владельца
## 8. Связи с другими D# и попутные дефекты (не заведены)
## 9. Замечания к формату (если есть)
```
