## Чем закрывает боли владельца

1. **home/end листают историю.** Архитектурная причина — дублирующий keybind по умолчанию
   (см. ось TUI-гигиена). Пять issue об этом закрыты как дубликаты/`not_planned`
   (#14899, #7190, #2649, #8344, #4143, #27661) — воспроизводится годами, ни разу не
   починено в дефолте, включая 1.18.29. Обходной путь ЕСТЬ и подтверждён в треде #27661
   пользователем `taviso`: в `tui.json` поставить `"messages_first":"none","messages_last":"none"`,
   тогда сработают штатные `input_buffer_home/end`. Я проверил (ЗАМЕРЕНО) только что такой
   `tui.json` в изолированном окружении (`XDG_CONFIG_HOME` на скретч-папку, конфиг
   владельца НЕ трогал) не роняет `opencode debug paths/config` — сам факт, что нажатие
   клавиш после правки реально даёт курсор, а не скролл, НЕ проверен (нужен живой TTY,
   `gh`/headless-прогон его не даёт). Итог: чинится конфигом, но подтверждение — ПО ДОКАМ
   для сути фикса + частично ЗАМЕРЕНО (конфиг грузится не ломая процесс).
2. **Субагент блокирует главную сессию.** Архитектурно: issue #5887 (главный тред,
   26 комментов, community просит именно fire-and-forget) и #15069 — оба `not_planned`.
   Комментаторы прямо называют это отставанием от Claude Code. Обходы — только внешние
   плагины (`oh-my-opencode`, `opencode-background-agents`, `Pocket-Universe`), причём
   `Pocket-Universe` сама зависит от НЕ смёрженных PR (#9272 `session.before.idle`, #7725 —
   #7725 к тому же ЗАКРЫТ, не смёржен). Починки внутри 1.18.29 нет. ПО ДОКАМ.
3. **У субагента нет поля ввода.** Это НЕ баг, а сознательное решение: в issue #6896
   мейнтейнер `rekram1-node` пишет буквально "this was intentional change" про скрытие
   prompt у child-сессии. Комьюнити-плагин `strayge/opencode-plugins/subagent-steering`
   возвращает поле ввода в подсессию, НО по его же README требует "a specific OpenCode
   fork featuring the `session.prompt.below` slot gate" — "on standard OpenCode builds,
   the plugin does nothing". То есть рабочего фикса на ВАНИЛЬНОЙ 1.18.29 нет, только
   форк. Архитектурно. ПО ДОКАМ.
4. **Воркер встрял, steer в очереди, главная сессия ждёт.** То же ограничение, что в п.4
   оси "Досылка": steer подхватывается только "в следующей безопасной точке" ЭТОЙ же
   сессии — а не форсированно и не через границу родитель→блокированный child. Прямые
   запросы на форс-чтение очереди закрыты `not_planned` (#24298, #16102); открытые дубли
   (#32157, #5408) без движения месяцами, с явным раздражением комьюнити в комментах
   ("let's make a fork NOW"). Архитектурно. ПО ДОКАМ.

Итог по всем четырём: ни одна боль не чинится флагом/настройкой из коробки; #1 частично
смягчается конфигом (с оговоркой не проверенного живого нажатия клавиш); #2/#3/#4 —
архитектурные, официально признаны `not_planned`, рабочих обходов без форка нет.

## Стоимость перехода

Не переизмерял — вне рамок задачи (обвязка PetBox уже поднята и используется владельцем
ежедневно: `opencode.json` содержит полный `agent`-блок с телами промптов ролей и
`"petbox":"managed"` опцией). Остаточная стоимость — то, что уже зафиксировано в снимке:
переписать provider-`limit` вручную под каждую модель (иначе режется контекст) и держать
`variant` синхронным с уровнем рассуждения. Хуков session-start/stop, аналогичных CC/droid,
в рамках этой инвентаризации не проверял (см. ниже).

## Чего не проверил и почему

- Реальное нажатие Home/End в живом TUI до и после правки `tui.json` — эта сессия не имеет
  интерактивного TTY для эмуляции клавиш; проверено только что конфиг синтаксически
  принимается и не роняет CLI.
- Плагины `oh-my-opencode`, `opencode-background-agents`, `subagent-steering` — не ставил
  и не гонял: `subagent-steering` по README не работает на ванильной сборке (требует форк),
  остальные two — вне границ задачи (не апгрейдить/не форкать среду владельца).
- Наличие и формат session-start/stop хуков в opencode (аналог CC/droid) — не проверял,
  не было в списке болей; если понадобится для сравнения "Обвязки PetBox" отдельно —
  нужен отдельный проход.
- Существование версии новее 1.18.29 — не проверено нужды: `gh release view` на
  `anomalyco/opencode` называет 1.18.29 последним тегом (опубликован 2026-09-04, за 4 дня
  до этой инвентаризации), т.е. на дату замера владелец УЖЕ на актуальной версии.
