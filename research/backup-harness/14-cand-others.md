# Кандидаты: OpenHands / Crush / Codex CLI / Gemini CLI + пятый

Дата: 2026-09-08 | Исполнитель: Claude Sonnet 5, petbox-worker | Источники: доки вендоров,
GitHub-репозитории, вторичные обзоры (WebSearch/WebFetch). ЗАМЕРЕНО нет нигде ниже —
ничего не устанавливалось (граница задачи), везде ПО ДОКАМ.

## Ворота (в порядке из брифа)
1. Терминальный агент? 2. Раздаваемость (свои ключи, без аккаунта вендора харнесса)?
3. Обвязка PetBox (MCP + хуки старт/стоп)?

## OpenHands (All Hands AI)

Вердикт: **не годится** — CLI-фронт официально не поддерживается вендором с 2026;
ставить не на что.

| ось | оценка | обоснование | статус |
|---|---|---|---|
| Ворота 1 | проходит | `openhands` — терминальный процесс (не только Docker/GUI), есть headless-режим для CI | ПО ДОКАМ |
| Ворота 2 | проходит формально | LiteLLM-роутинг, `LLM_API_KEY`/`LLM_BASE_URL` через `--override-with-envs`, 100+ провайдеров, аккаунт вендора не требуется | ПО ДОКАМ |
| Ворота 3 | есть MCP, хуки слабые | `openhands mcp add/list`; хуки — `~/.openhands/hooks.json`, но описаны как pre/post-tool, конкретно session-start-с-контекстом / session-end-с-транскриптом в найденных доках НЕ подтверждены | ПО ДОКАМ, неполно |
| Лицензия | MIT | репозиторий OpenHands/OpenHands-CLI | ПО ДОКАМ |

Ключевой факт, решающий вопрос: README `OpenHands/OpenHands-CLI` прямо гласит
"⚠️ This project is no longer actively maintained", вендор рекомендует другой продукт
("Agent Canvas") взамен. Мёртвый сопровождением CLI не стоит тащить в запасной харнесс,
даже если ворота 1–3 формально проходимы — некому будет чинить регрессии.

## Crush (Charm)

Вердикт: **годится с оговоркой** — все ворота проходит, но хуки "preliminary" и лицензия
не OSI-open-source до конверсии.

| ось | оценка | обоснование | статус |
|---|---|---|---|
| Ворота 1 | проходит | нативный терминальный TUI, наследник opencode от той же студии | ПО ДОКАМ |
| Ворота 2 | проходит | BYOK явный: `OPENAI_API_KEY`/`ANTHROPIC_API_KEY` и т.п. через env или built-in picker, аккаунт Charm не требуется | ПО ДОКАМ |
| Ворота 3 | MCP полный, хуки предварительные | MCP: stdio/HTTP/SSE в `crush.json`. Хуки: `docs/hooks` заявлены как "preliminary support", в найденном `AGENTS.md` описаны как **tool-хуки** ("fire before tool execution"), а не session-start/session-end с контекстом/транскриптом — нужен отдельный взгляд в `HOOKS.md`, не проверено | ПО ДОКАМ, неполно |
| Лицензия | FSL-1.1-MIT | не OSI-approved, конвертируется в MIT спустя срок (Functional Source License) — узнаваемая модель Charm/Sourcegraph, конкретный срок конверсии не проверен | ПО ДОКАМ |
| Делегирование | есть намёк | `AGENTS.md`: "Coordinator: manages named agents (coder, task)" — многоагентность заявлена, механика не описана в найденном фрагменте | ПО ДОКАМ, неполно |

## Codex CLI (OpenAI)

Вердикт: **годится, кандидат на глубокий разбор** — все три ворота проходит по докам,
хук-система почти зеркальна Claude Code.

| ось | оценка | обоснование | статус |
|---|---|---|---|
| Ворота 1 | проходит | нативный терминальный агент, `~/.codex/config.toml` | ПО ДОКАМ |
| Ворота 2 | проходит, это главный вопрос брифа | `OPENAI_API_KEY` заданный — Codex использует его и ИГНОРИРУЕТ залогиненную ChatGPT-сессию; поддержаны кастомные `model_providers` (OpenRouter и т.п.) — т.е. BYOK без привязки к аккаунту OpenAI как таковому, хотя бренд тот же, что у модели | ПО ДОКАМ |
| Ворота 3 | MCP + хуки почти 1:1 с CC | Хуки `hooks.json`/`[hooks]` в config.toml с v0.114 (март 2026): `SessionStart` (source: startup/resume/compact, есть `additionalContext`, добавляется как developer-message), `SessionEnd` (`session_id`, `transcript_path`, `reason` — пока всегда `other`). Общие поля входа: `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `model` | ПО ДОКАМ |
| Делегирование | есть субагенты | Документированы `Subagents`, аудит-лог с "subagent context and full delegation provenance"; `SessionEnd` явно НЕ срабатывает для субагентов (асимметрия с root-сессией) | ПО ДОКАМ, неполно |
| Лицензия | Apache-2.0 | `openai/codex` на GitHub (общеизвестно, не перепроверялось отдельным фетчем) | ПО ДОКАМ |

Обвязка PetBox по этой оси выглядит переносимой почти 1:1 (адаптер формата, не переписывание
с нуля) — сопоставимо с droid, а не с "писать заново" как у pi.

## Gemini CLI (Google)

Вердикт: **не годится как основной запасной вариант** — ворота 2 и 3 формально пройдены,
но продукт в процессе вытеснения вендором.

| ось | оценка | обоснование | статус |
|---|---|---|---|
| Ворота 1 | проходит | терминальный агент, `google-gemini/gemini-cli` | ПО ДОКАМ |
| Ворота 2 | пройдено, но подрезано | своим API-ключом (Gemini API/Vertex) работать можно; НО 18 июня 2026 Google отключил бесплатный/Google One тир Gemini CLI без периода отката, переведя усилия на новый продукт Antigravity CLI — сохранили доступ только платные Code Assist Standard/Enterprise или платный API-ключ Gemini Enterprise Agent Platform. Для чистого BYOK на "просто Gemini API key" ситуация требует отдельной проверки, не совпадает ли это с отключённым тиром | ПО ДОКАМ, неполно |
| Ворота 3 | MCP + хуки полные | Хуки с v0.26.0+, включены по умолчанию: `SessionStart`/`SessionEnd`/`Notification`/`PreCompress` + tool/model/agent-хуки. `SessionStart.additionalContext` — "injected as first turn" (интерактив) / "prepended to prompt" (headless). `SessionEnd` даёт только `reason` (exit/clear/logout/prompt_input_exit/other) — **транскрипт НЕ передаётся**, это слабее Codex/CC | ПО ДОКАМ |
| Лицензия | Apache-2.0 (общеизвестно) | не перепроверялось отдельным фетчем | ПО ДОКАМ |

Вывод по воротам 2+3: технически лучший MCP/хуки среди всех четырёх (события богаче, чем у
Crush), но вендор явно сворачивает продукт в пользу Antigravity — закладываться на CLI,
которую переводят в режим доживания, рискованно для роли "запасной харнесс".

## Пятый кандидат вне списка: Qwen Code (Alibaba, QwenLM/qwen-code)

Открытый терминальный агент, форк архитектуры gemini-cli, активно развивается в 2026.

| ось | оценка | обоснование | статус |
|---|---|---|---|
| Ворота 1 | проходит | "AI coding agent that lives in your terminal" | ПО ДОКАМ |
| Ворота 2 | проходит | мультипротокол: OpenAI/Anthropic/Gemini/Qwen API + любой OpenAI-совместимый эндпоинт или локальная модель (Ollama/vLLM), переключение `/auth` в рантайме; регистрация в Alibaba/Qwen для стороннего ключа по найденным докам не требуется (не проверено на 100%) | ПО ДОКАМ, неполно |
| Ворота 3 | MCP + хуки полные, похоже на CC | MCP-менеджмент без рестарта. Хуки: `SessionStart` (matcher source: startup/resume/clear/compact) и `SessionEnd` (matcher reason: clear/logout/prompt_input_exit и т.д.) — то есть системa хуков структурно ближе к CC/Codex, чем урезанный Gemini CLI SessionEnd; передача транскрипта в SessionEnd отдельно не подтверждена | ПО ДОКАМ, неполно |
| Делегирование | заявлено | "SubAgents, Agent Teams" в списке фич | ПО ДОКАМ, неполно |
| Лицензия | Apache-2.0 | github.com/QwenLM/qwen-code | ПО ДОКАМ |

Qwen Code проходит все три ворота по докам и не входит в список уже покрытых (droid,
opencode, pi, Aider, Cline, Goose). Он ближе к "нужен глубокий разбор", чем Gemini CLI,
именно из-за судьбы последнего у вендора — стоит рассмотреть как второй кандидат наравне
с Codex CLI, а не как третий по счёту.

## Кто идёт на глубокий разбор

**Codex CLI** — проходит все три ворота увереннее прочих: хук-система почти зеркальна
Claude Code (SessionStart+additionalContext, SessionEnd+transcript_path), BYOK подтверждён
явно (`OPENAI_API_KEY` игнорирует ChatGPT-логин), есть субагенты.

**Qwen Code** — второй кандидат: тоже все три ворота, но SessionEnd/транскрипт и
"без аккаунта Alibaba" не проверены так же строго, как у Codex.

Оба требуют отдельного инвентаря с живым прогоном (ЗАМЕРЕНО) — в этом файле только доки.

## Чего не проверял и почему

Ничего не устанавливалось (граница задачи "ничего не ставить на машину"). Не проверено:
живой запуск любого из пяти кандидатов; точный срок конверсии FSL-1.1-MIT→MIT у Crush;
детали `HOOKS.md` Crush (session-level события отдельно от tool-хуков); формат
`transcript_path` у Qwen Code SessionEnd; действительно ли "чистый" Gemini API ключ (не
Enterprise Agent Platform) пережил отключение 18 июня 2026 — источники расходятся в деталях
carve-out.
