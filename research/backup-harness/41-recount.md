# Пересчёт выбора с учётом оверхеда: Qwen Code против Codex CLI

2026-09-08, оркестратор. Основание пересчёта: замер `35-bench-overhead.md` показал, что
выбранный кандидат — самый дорогой на старте из всех, а Codex после доведения до равного
уровня (`33-codex-full.md`) поднялся на второе место. Решение D1 принималось, когда обеих
цифр не было.

## Где они действительно расходятся

Оси, по которым оба ✅ (независимость от вендора, MCP живьём, инжект в первый ход,
делегирование, открытая лицензия), опускаю — они не различают.

| | Qwen Code 0.23.0 | Codex CLI 0.153.4 |
|---|---|---|
| Стартовый оверхед | **22.4k** (холодный 31.5k) | **8.7k** |
| Стоимость задачи (B1/B2) | 44.6k | 27.5–37k |
| Ходов на задачу (среднее) | **2.00** | 3.33 |
| Файловый инструмент | `write_file` есть | **нет** — только `exec_command` |
| Потолок исполнения | **жёсткий kill 120 с** | yield каждые ~30 с, процесс жив |
| Досылка после потолка | **доходит** (ход закрыт) | **не доходит** (ход не закрыт) |
| Продолжаемость | ✅, кроме продолжения после отмены | **✅ шире** — `interrupt_agent` не терминален |
| Хуки в headless | `SessionEnd` не вызывается | оба молча пропускаются без флага |
| Windows в CI | **снята с PR-гейта**, раз в сутки на main | **обязательные джобы** x64 и arm64 |
| Живые Windows-issues | утечки ConPTY/conhost, кодировка CP-866 | setup-loop песочницы, экранирование |
| Модель при спавне + гейт | ✅ белый список в рантайме, хук видит `model` | ✅ то же, подтверждено по коду |
| Правка системного промпта | замена или append целиком | **замена, append И точечные `include_*`** |

## Что решает в пользу Qwen

**Главная боль закрывается только у него.** Разница тоньше, чем «у обоих есть потолок».
Qwen убивает зависший вызов — ход ЗАКРЫВАЕТСЯ, и накопленная очередь применяется: владелец
получает возможность сказать застрявшему воркеру, что тест висит. Codex возвращает
управление модели каждые ~30 с, но ход при этом НЕ закрывается: модель переопрашивает
процесс внутри одного незакрытого хода, и внешняя досылка не долетает — те же 187 секунд
тишины, что и в первом замере, просто по другой причине. Для сценария «воркер встрял, я уже
написал причину» Codex не годится, а Qwen годится.

**Инструментарий.** У Codex нет файлового инструмента вовсе — запись идёт через shell,
отсюда и лишние ходы (3.33 против 2.00). Для кодинг-агента это не косметика: правка файлов
через `exec_command` менее предсказуема, чем через выделенный инструмент.

## Что решает в пользу Codex

**Стартовый оверхед втрое ниже** — 8.7k против 22.4k, а с холодным стартом Qwen (31.5k) —
почти вчетверо. Наш MCP на 122 инструмента ляжет сверху у обоих, но у Qwen поверх худшей базы.

**Продолжаемость шире:** `interrupt_agent` не терминален, прерванный агент остаётся
резидентным. У Qwen продолжение отменённой сессии запрещено (идентификатор при этом не
теряется).

## Развилка ЗАКРЫТА: оверхед амортизируется, а не умножается

Замерено (`36-cache-friendliness.md`, живой прогон через прокси на DeepSeek, по 4 хода на
кандидата, счётчики самого провайдера):

| | ход 1, полная ставка | ходы 2–4, полная ставка |
|---|---|---|
| Qwen Code | 18 290 токенов | **53–375 за ход** (попадание 96–100 %) |
| Codex CLI | 239–353 (ход был прогрет прошлым прогоном) | 239–353 за ход (96–97 %) |

Динамические блоки — дата, окружение — вставляются ОДИН раз на старте сессии и не
переставляются на каждом ходе: харнесс свой же кэш не ломает. Это проверялось отдельно.

**Следствие для выбора.** Трёхкратный разрыв стартового оверхеда — это разница примерно в
9k токенов ОДИН раз за сессию, а не на каждом ходе. После первого хода оба кандидата стоят
сотни токенов за ход. Довод «Codex втрое дешевле» сжимается до «Codex дешевле на один
первый ход» и перестаёт быть решающим.

> [!NOTE]
> Методическая находка, полезная за пределами этой задачи: сырой байтовый префикс запроса
> расходится рано (на 35–55 %), потому что массив `tools` сериализуется ПОСЛЕ растущего
> массива сообщений — а попадание в кэш при этом 96–100 %. Значит побайтовое сравнение
> запросов НЕ годится как признак работы кэша; верить можно только счётчикам провайдера.

## Вывод (переписан 2026-09-08 после трёх проверок)

**Оба довода, на которых держался выбор Qwen, оказались ошибками измерения.** Резерв
указал на первый, прогоны подтвердили оба.

1. **«Только Qwen закрывает боль» — неверно.** Стенд мерил не тот канал: `codex queue` это
   очередь ПОСЛЕ хода и долететь в незакрытый ход не может в принципе. Настоящий канал —
   **steer**, и через него идёт `send_input` оркестратора к воркеру. Живой прогон на вечном
   `hang.sh` (`39-codex-steer.md`): сообщение дошло внутрь незакрытого хода за ~90 с, модель
   процитировала содержание, убила зависший процесс, а вымышленную половину инструкции
   отвергла — то есть прочитала текст, а не совпала с шаблоном.
2. **«У Codex нет файлового инструмента» — неверно.** `apply_patch` включается через
   `model_catalog_json` в `config.toml` (`42-codex-apply-patch.md`, подтверждено живьём:
   9 инструментов против 10). И он РАБОТАЕТ на DeepSeek (`43-apply-patch-behaviour.md`):
   0 отклонений из 2 вызовов, 0 повторов, верный синтаксис с первой попытки, корректность
   4/4 по `diff`. Ходов не сэкономил (3.5 против 3.5), но задача обошлась **на ~30 %
   дешевле** — 23.6k против 33.8k токенов.

### Что осталось у каждого

**За Codex:** стартовый оверхед втрое ниже (амортизируется, но первый ход дешевле), шире
продолжаемость (`interrupt_agent` не терминален), крепче Windows (обязательные CI-джобы
против снятой с PR-гейта ноги у Qwen с утечками ConPTY и CP-866), точечные `include_*` для
правки промпта, и досылка доходит БЕЗ убийства процесса.

**За Qwen:** адаптер почти бесплатен — он CC-клон, роли и транскрипт в формате Claude Code,
тогда как под Codex нужен рендерер TOML и свой парсер rollout. Плюс `apply_patch` там
родной, а не включённый через кастомный каталог моделей.

### Решение

**Внедрять первым Codex CLI**, как и предложил резерв. Причина не в сумме галочек, а в том,
что весь недостающий опыт — про него: его слабости оказались артефактами измерения, его
Windows крепче на машине владельца, и именно он требует недель эксплуатации, чтобы стать
понятным. Qwen как CC-клон догоняется одним проходом воркера в любой момент.

**Qwen Code — второй в очереди, не отменённый.** Пара внедряется целиком; сужение до одного
преждевременно, пока нет опыта эксплуатации ни по одному из них.

**Адаптер opencode заморозить, а не удалять** (тоже совет резерва): это единственный
харнесс с ежедневным опытом, удалить его дёшево позже, восстановить — дорого. Droid
уходит без потерь: зависимость от аккаунта Factory противоречит самой цели «страховка от
подписки».
