## Чем закрывает боли владельца

- home/end: по конфигу не воспроизводится (см. TUI-гигиена).
- Блокировка главной сессии субагентом / отсутствие поля ввода у субагента: не проверено — зависит от
  реализации `examples/extensions/subagent`, которая работает через фоновые `exec`-процессы, а не через
  собственный TUI-режим субагента; сам pi RPC не блокируется на дочерних exec по документации, но живого
  прогона делегирования не делалось (вне безопасных границ задачи).
- Застрявший воркер игнорирует очередь: закрывается штатно через `steer` — сообщение доставляется на
  границе текущего tool-call, не после завершения всего запроса.

## Стоимость перехода

MCP-эквивалент для petbox-вербов: обвязка `registerTool()` под REST-вызовы PetBox (как и было в
снимке) — без изменений, петбокс-MCP-клиента внутри pi нет и не появился.
Хук-эквивалент: extension-файл на TS с `pi.on("session_start")`/`before_agent_start` для инжекта
canon-контекста и `session_shutdown`/`agent_end` для выгрузки `event.messages` в PetBox session —
API есть и задокументирован, но реализация полностью на владельце ("хакать своими руками"). По объёму
это два обработчика событий + вызов REST — порядка 50-100 строк TS по образцу `examples/extensions/`
(в пакете их 2602+1137+1408 строк доков и десятки готовых примеров-заготовок для разных хуков).
Делегирование: адаптация `examples/extensions/subagent/` (index.ts 1009 строк) — не с нуля, но и не
тривиально; основной риск — совместимость версии примера с 0.78.0 не проверялась.

## Стоимость перехода

MCP-обвязка: писать REST-клиент к PetBox с нуля, как и в снимке для pi — готового расширения-точки
нет вообще (ни extension-API, ни MCP-клиента).
Хук-эквивалент: жизнеспособного пути кроме внешнего вотчера над `.aider.chat.history.md` +
`--notifications-command` как грубый триггер "конец хода" не просматривается; canon-инжект на старт
сессии придётся делать через `--message`/`--read`-файл, подсовываемый при каждом запуске процесса
(не событие, а параметр запуска) — это дешевле по коду, чем у pi, но качественно слабее (нет доступа
к живому состоянию сессии, нет структурированного транскрипта на выходе).
Делегирование: architect/editor duo не расширяется до N ролей без форка кода — не оценивается как
"адаптер", это переписывание.

## Поправка владельца, 2026-09-08

Дописано оркестратором со слов владельца, отдельным блоком — инвентарь выше не переписан.

**MCP у pi подключается ПЛАГИНАМИ**, в частности через сборку oh-my-pi. То есть вывод
«MCP нет, и это намеренно» верен для ЯДРА pi, но не описывает реальную установку.
Строку «MCP» в таблице осей считать неполной; если pi выйдет в финал — проверять отдельно
и живьём, какие именно вербы доезжают через плагинный MCP.

**Практический вердикт владельца.** Если ставить целью довести интеграцию PetBox внутрь
агента, pi — чуть ли не лучший кандидат: ядро минимальное, всё расширяемо. Но цена —
собирать и сопровождать собственную сборку, а владельцу это не нужно. Поэтому pi остаётся
в матрице с понижением НЕ по технике, а по стоимости сопровождения: «дорог в поддержке
для этой задачи», а не «слаб».
