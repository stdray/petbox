## Рамка задачи

Владелец держит Claude Code основным. Проблема: при истечении подписки Claude Code
перестаёт работать целиком, даже с чужими провайдерами. Нужна запасная обвязка.
Droid держится как запасной уже сейчас. Opencode настроен, но раздражает на
содержательной работе. Отдельно ценно иметь ЧИСТО OPENSOURCE вариант про запас.
Решение принимается по фактам исследования, не по предпочтению.

## Droid (Factory), 0.170.0

ЗАМЕРЕНО 2026-09-08 на машине владельца (интерактивный логин пройден, FACTORY_API_KEY не задан):

- `droid exec` на custom-модели (свои ключи) — РАБОТАЕТ, exit 0, PetBox-инжект на месте.
- `droid exec -m claude-haiku-4-5-20251001` (built-in модель Factory) — ПАДАЕТ:
  "Authentication failed. Please log in using /login or set a valid FACTORY_API_KEY".
- `droid exec --mission` — ПАДАЕТ с той же auth-ошибкой ДАЖЕ при `--worker-model custom:...`.
  Плюс требует `--auto high` или `--skip-permissions-unsafe`.
- Валидация `--worker-model` и `--validator-model` честная: битый id отвергается сразу
  с перечнем каталога, тихого отката на дефолт НЕТ.

Вывод: граница проходит ПО МОДЕЛИ, а не по режиму. Память `m-464b5387ad2545ce8e195279e086167e`.

ЗАМЕРЕНО 2026-08-29 (карта паритета, память `m-38a514a22cb0466a86d0d1eec29073c6`):

- нет аналога `default_agent` — сессия не стартует как petbox-orchestrator;
  обход `--append-system-prompt-file`, это флаг запуска, а не настройка;
- субагенту не выдаётся Task, вложенность жёстко 1;
- `reasoningEffort` СТИРАЕТСЯ нашим компилятором кита (он знает только name, description,
  model, mcpServers) — устранимо правкой кита;
- `droid exec` без `--auto` НЕ read-only: autonomyLevel high в settings перекрывает CLI.

ЗАМЕРЕНО ранее (память `m-240a36080b574c4db0b34aabdb4c3056`): CC-совместимые хуки,
9 событий, SessionStart с additionalContext, Stop с transcriptPath; полноценный MCP;
плагины со SKILL.md. Обвязка переносится почти 1:1, нужен адаптер формата транскрипта.

ПО ДОКАМ: Missions требуют платный план и включённый Extra Usage, независимо от BYOK.

ЗАМЕРЕНО 2026-09-08 в чистом Docker-контейнере (`node:22`, без `~/.factory` владельца,
без `FACTORY_API_KEY`, без логина; смонтирован только `settings.json` с одной
custom-моделью). Замер сделан ДВАЖДЫ: исполнителем песочницы и оркестратором независимо.

- `droid exec -m custom:<id>` — **РАБОТАЕТ**, ответ модели, exit 0. Аккаунт Factory не нужен.
- Барьер различён: отсутствие auth и фиктивный `FACTORY_API_KEY` дают ошибку Factory
  ("Authentication failed... /login"), а фиктивный ключ ПРОВАЙДЕРА даёт 401 от самого
  провайдера — то есть успех выше настоящий, а не молчаливый откат.
- **Интерактивный `droid`** при тех же настройках рисует TUI, но упирается в экран
  "Please login with your Factory account to continue".

Вывод, отменяющий прежний: граница проходит НЕ только по модели, но и по режиму —
**headless раздаваем, интерактивный требует аккаунта**. Для сценария «отдать другу»
это означает: скриптовый droid на своих ключах отдать можно, привычную TUI-сессию — нет.

ПО ДОКАМ: бесплатного тарифа Factory нет, Pro от $20/мес. Требует ли САМА регистрация
аккаунта карту — не выяснено (страница SPA, регистрацию сознательно не проходили).

## Opencode, 1.18.29

Боли владельца из ежедневной работы (наблюдение, не из интернета):

- home/end в поле ввода листают экраны истории вместо перемещения по вводу;
- запуск субагента БЛОКИРУЕТ главную сессию;
- у субагента нет поля ввода вообще — дослать сообщение в долгую работу невозможно;
- воркер встрял на зависшем тесте: главная сессия ждёт, хотя причина уже в очереди.

ЗАМЕРЕНО ранее: есть `default_agent` (без него сессия стартует на встроенном build);
самописный provider-блок с руками прописанным `limit` РЕЖЕТ контекст встроенной модели;
уровень рассуждения задаётся через `agent.<имя>.variant`.

## Pi (oh-my-pi)

УСТАРЕЛО (было записано «ни MCP, ни хуков»). Уточнено 2026-09-08 по `13-cand-pi-aider.md`:

- **Хуки ЕСТЬ.** Установленная версия (0.78.0 против 0.85.1 в npm) несёт документированный
  API событий жизненного цикла: `session_start`, `before_agent_start` — с ИНЖЕКТОМ
  контекста, то есть аналог того, что нам нужно на старте, — и `agent_end` /
  `session_shutdown` для доступа к транскрипту.
- **Нативный `steer` (RPC).** Механизм досылки в работающую сессию, по описанию лучше
  того, чего не хватает в opencode. Это прямое попадание в главную боль владельца.
- **MCP по-прежнему НЕТ**, и это намеренно («intentionally does not include built-in MCP»
  в докax, ни одного упоминания mcp в свежем CHANGELOG). PetBox-вербы — только через REST.

Прежняя оценка «приоритет низкий» опиралась на утверждение про отсутствие хуков и
теперь требует пересмотра.
