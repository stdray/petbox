# Реестр решений

Составлено оркестратором 2026-09-08 по итогам всех инвентарей, консолидации и трёх живых
стендов. Формат: РЕШЕНИЕ — ЦЕНА — ЧТО ЛОМАЕТСЯ, ЕСЛИ НЕ ПРИНЯТЬ. Не список вопросов:
вопрос ничего не двигает, решение с последствиями двигает.

Владелец решает по фактам; ниже факты уже отделены от выводов.

## Открытие, которое меняет постановку

**Боль «воркер встрял, а сообщение не доходит» не решается выбором харнесса.**
Замерено на общем стенде (`22-steering-bench.md`) на четырёх кандидатах: НИ ОДИН не
доставляет сообщение агенту, застрявшему внутри tool-call. Все реализации досылки —
доставка НА ГРАНИЦЕ хода, а у зависшего вызова граница не наступает никогда.

Единственное, что реально сработало, — **таймаут на tool-call**: он сам создаёт границу,
после которой очередь применяется. Есть только у Qwen Code (жёсткие 120 с).

Отсюда: искать «харнесс с досылкой» было неверной постановкой. Правильная —
«харнесс с потолком ожидания».

| кандидат | досылка | таймаут tool-call | закрывает боль |
|---|---|---|---|
| Qwen Code 0.23.0 | на границе | **есть, 120 с** | частично — потолком ожидания |
| Codex CLI 0.153.4 | на границе | нет (187 с тишины) | нет |
| pi 0.85.1 | на границе (~23 с в контроле, 0 за 195 с на висе) | нет | нет |
| droid 0.213.0 | не доходит вовсе | не проверен | нет |
| opencode 1.18.29 | на границе, закрыто как `not_planned` | нет | нет |

## D1. Запасная обвязка — Qwen Code

**Решение.** Взять Qwen Code основным кандидатом в запасные.
Основания, все уровня «по коду» или «живой прогон»: Apache-2.0; BYOK — единственный путь
(вендорский OAuth-тир для новых пользователей мёртв прямо в коде); оба хука реальны и
подключены к рабочим путям; BYOK на DeepSeek подтверждён живым прогоном; таймаут 120 с —
единственная в обзоре вещь, которая реально спасает от зависшего воркера.

**Цена.** Писать адаптер обвязки под его формат хуков. Не проверены: MCP с нашим сервером
живьём, TUI-гигиена (home/end), доступ к транскрипту на завершении (по `14` — SessionEnd
без транскрипта, это надо закрывать до внедрения).

**Что ломается, если не принять.** Остаёмся без раздаваемой среды: ни один другой
кандидат нельзя отдать человеку без аккаунта вендора И с рабочей обвязкой одновременно.

## D2. Droid — оставить, но переопределить роль

**Решение.** Droid остаётся, но не как «запасная среда», а как **headless-движок** для
handoff-скиллов. Раздавать как среду его нельзя: `droid exec` на своих ключах работает на
чистой машине без аккаунта (замерено дважды), а интерактивный TUI упирается в экран
логина Factory.

**Цена.** Признать, что при уходе Claude Code привычной TUI-работы на droid не будет —
без аккаунта Factory, а бесплатного тарифа у них нет.

**Что ломается.** Если считать droid полноценным запасным, обнаружится это в худший
момент — когда подписка уже кончилась.

## D3. Opencode — вывести из кандидатов

**Решение.** Не рассматривать как запасную обвязку. Все четыре боли владельца либо
закрыты мейнтейнерами как `not_planned`, либо названы намеренным поведением; версия у
владельца уже самая свежая, ждать нечего.

**Цена.** Вложенная в него настройка остаётся, но развивать её как запасной путь смысла нет.

**Что ломается.** Продолжаем тратить внимание на инструмент, чьи ключевые для нас дефекты
проект отказался чинить.

## D4. Pi — не брать, но не из-за техники

**Решение.** Не брать. Причина НЕ «слаб»: у pi минимальное ядро, есть хуки с инжектом,
MCP подключается плагинами (oh-my-pi). Причина — стоимость: нужна и сопровождается
собственная сборка, а владельцу это не нужно. Плюс замерено: `steer` — boundary-only,
главную боль не закрывает.

**Цена.** Отказ от самого гибкого варианта интеграции PetBox внутрь агента.

**Что ломается.** Если когда-нибудь цель сменится на «довести интеграцию до конца» —
решение придётся пересматривать, и pi будет первым кандидатом.

## D5. DeepSeek Harness — не среда, но источник идей

**Решение.** Не рассматривать как замену среде: интерактивного TUI в поставке нет вовсе
(то, что похоже на него в `--help`, — пример под самостоятельную сборку). Забрать идеи и
перепроверить у себя два его дефекта, потому что они наши тоже.

**Цена.** Ноль, кроме времени на чтение.

**Что ломается.** Теряем два предупреждения, добытых живьём: SessionStart-хуки, запущенные
detached, промахиваются мимо ПЕРВОГО хода (инжект приезжает во второй), а `transcript_path`
может приходить пустым. Обе — ровно те грабли, на которые наша обвязка ложится.

## D6. Ввести «потолок ожидания» как требование, а не как свойство кандидата

**Решение.** Считать таймаут на tool-call обязательным требованием к любой обвязке, и там,
где харнесс его не даёт, обеспечивать самостоятельно — на уровне запускаемых команд.

**Цена.** Дисциплина: каждая потенциально висящая команда должна запускаться с таймаутом.

**Что ломается.** Без этого сценарий «воркер висит, владелец уже написал причину» остаётся
неразрешимым на ЛЮБОМ харнессе — это доказано стендом, а не предположено.

## D7. Отсев

Cline (хуки заявлены только под macOS/Linux, досылки нет), Goose (события есть, но
SessionStart/SessionEnd наблюдательные — инжекта нет), Aider (ни MCP, ни хуков; 3.5 месяца
без пушей), OpenHands (CLI официально не сопровождается), Gemini CLI (вендор сворачивает
тир), Crush (хуки помечены вендором как preliminary; лицензия не OSI).

**Цена отсева.** Cline и Goose оценены только по докам — если решение по D1 сорвётся,
их придётся перепроверять по коду, а не добирать по README.

## Проверки D1 — статус на 2026-09-08

**Обе блокирующие ПРОЙДЕНЫ, D1 устоял.** Детали — `25-qwen-wiring.md`.

1. **MCP с нашим сервером — НЕ блокирует.** `qwen mcp list` даёт `✓ Connected`;
   перехватом исходящего запроса к модели насчитано **95 вербов `mcp__petbox__*` из 122
   инструментов**; живые читающие вызовы `whoami` и `memory_search` вернули реальные
   данные. Перепроверено оркестратором независимо: чистый контейнер, Qwen Code 0.23.0,
   свой изолированный `settings.json` — `✓ petbox ... Connected`.
2. **Транскрипт на завершении — НЕ блокирует.** SessionEnd-хук получает `transcript_path`,
   и файл по нему на момент работы хука уже дописан. Утверждение из `14` про gemini-cli
   на Qwen Code НЕ переносится — родство архитектуры не означает совпадения поведения.

### Две находки с ценой, обязательные к учёту при внедрении

- **Наш `.mcp.json` как есть не заработает.** Он гейтится по scope на подтверждение и, что
  важнее, **не раскрывает `${PETBOX_API_KEY}`**: резолвер переменных применяется только к
  settings-файлам. Рабочая форма — `~/.qwen/settings.json` либо `--mcp-config`.
- **В headless (`-p`) SessionEnd не срабатывает вовсе**, хотя транскрипт при этом пишется.
  Разобрано по коду (`28-qwen-headless-sessionend.md`): это **дизайн, а не гонка**.
  `fireSessionEndEvent` имеет ровно четыре места вызова, и все — на слое UI/ACP;
  `nonInteractiveCli.ts` не вызывает его нигде. Headless выходит своим путём
  `runNonInteractive` → `runExitCleanup` → `process.exit`.

  **Хорошая новость и готовое решение:** транскрипт ДОКАЗУЕМО полон к моменту выхода —
  перед выдачей результата headless дожидается `finalize()` и `flush()` записи чата.
  Значит обход детерминированный, а не «повезёт-не повезёт»: **wrapper читает
  `chats/<sessionId>.jsonl` после выхода процесса**, по session_id. Хук для этого не нужен.
  `SessionStart` и `Stop` в headless срабатывают (они живут в core), но преимущества перед
  чтением файла не дают. Заводить issue/PR наверх не стоит — обход на нашей стороне проще
  и надёжнее.

### Проверки 3 и 4 — тоже пройдены (детали: `26-qwen-inject-tui.md`)

3. **Инжект попадает в ПЕРВЫЙ ход.** По коду `SessionStart` не detached: вызов вложен в
   цепочку `await` вплоть до `initialize()`, которую CLI обязан дождаться. Живьём
   (mock-эндпоинт в контейнере) маркер оказался в запросе №1. Гонка, найденная у DeepSeek
   Harness, воспроизводится ТОЛЬКО при явном опт-ауте `"async": true` на хуке — тогда
   маркер не долетает вообще ни до одного запроса. Практический вывод: `async` на хуке
   инжекта не ставить никогда.
4. **Home/End работают правильно.** По коду голые Home/End привязаны к перемещению курсора
   в строке, Ctrl+Home/End — отдельная команда скролла; конфликта с историей нет. Живой
   PTY-тест через tmux подтвердил посимвольно. Многострочность (Ctrl+J) и вставка из
   буфера тоже проверены живьём. То есть боль, с которой начался весь поиск, у Qwen Code
   отсутствует.

### Осталось (не блокирует решение)

5. ~~Продолжаемость субагента~~ — **ЗАКРЫТО**, детали в `27-qwen-resumability.md` (по коду,
   с file:line). Дефолтный фоновый путь Qwen Code воспроизводит контракт Claude Code, а не
