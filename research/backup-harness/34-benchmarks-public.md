# Публичные бенчмарки харнессов (не моделей)

Составлено 2026-09-08. Критерий: из бенчмарка можно вычленить вклад ХАРНЕССА — одна модель
через разные обвязки, либо явно измерен оверхед обвязки. Всё — ПО ДОКАМ, ничего не прогонялось.

## Годятся (модель зафиксирована, харнесс — переменная)

**Composio, 8 харнессов на Kimi K3** — composio.dev, 04.08.2026 (live-замер самого Composio,
не репост). Модель Kimi K3 зафиксирована, 25 задач, 8 харнессов: pi Agent (мин. токенов,
~316K/задачу), Kimi Code (макс., 15.27M/24 задачи), Claude Code, Hermes и др. Разброс
успешности 68–88% (20 п.п.) при том же наборе тулов. Пересечение с нашими кандидатами:
**pi, Claude Code**. — ДА, прямое сравнение харнессов.
https://composio.dev/content/best-ai-agent-harnesses

**Systima / разбор Kunal Ganglani — оверхед системного промпта** — kunalganglani.com,
13.07.2026, источник — Systima Applied Research (12.07.2026). Прокси-логирование сырого
HTTP-трафика Claude Code и OpenCode к Anthropic API, модель зафиксирована (claude-sonnet-4.5,
доп. прогон на Claude Fable 5), вычтена константа шлюза 6200 токенов. Результат: Claude Code
шлёт ~33k токенов до первого пользовательского ввода, OpenCode ~7k (разрыв 4.7x); Claude Code
пишет до 54x больше cache-write токенов из-за нестабильного префикса запроса. Пересечение:
**Claude Code, opencode**. Замечание с HN: тестировали на устаревшей модели (объяснение —
экономия через Claude Max), не искажает сам разрыв по системному промпту. — ДА, это именно
измерение оверхеда обвязки.
https://www.kunalganglani.com/blog/opencode-vs-claude-code-token-overhead ·
https://www.developersdigest.tech/blog/claude-code-token-overhead-opencode-comparison

**arXiv 2607.22585, "The Scaffold Effect in Coding Agents"** (Vats & Golev, препринт
08.06.2026, DL4C@ICML 2026). Харнессы Goose, OpenCode, OpenHands-SDK на ДВУХ фиксированных
моделях (Qwen 3.6 Plus, MiniMax M2.5). Итог: разброс до 40x по токенам на решённую задачу при
разбросе успешности всего 0–8 п.п. между харнессами на той же модели — токены и точность
расходятся. Пересечение: **opencode, Goose**. — ДА, но модели не из нашего обихода (не
Claude/Qwen Code CLI/GPT), поэтому переносить абсолютные цифры на наших кандидатов нельзя,
только качественный вывод «харнесс двигает токены сильнее, чем точность».
https://arxiv.org/html/2607.22585

**arXiv 2605.27922, "Harness-Bench"** (27.05.2026, v1). 106 офлайн-задач, 5194 траектории,
ЯВНО контролирует модель и варьирует конфигурацию харнесса (completion, токены, безопасность,
устойчивость). Конкретные имена харнессов из реферата не подтверждены (глубже не проверялось)
— методологически годен, охват кандидатов не подтверждён.
https://arxiv.org/html/2605.27922v1

**Artificial Analysis Coding Agent Index — «Harness Comparison»** (запущен 05.2026, текущая
v1.4). На странице явно заявлено: «holds the underlying model constant at Claude Opus 4.7 and
compares … across different coding-agent harnesses» — Claude Code, Cursor CLI, opencode.
Точные числа не удалось вытащить через фетч (динамический чарт), но методология подтверждена
текстом методологии/страницы. Пересечение: **Claude Code, opencode** (Cursor CLI — не наш
кандидат). — ДА по конструкции, но нужен ручной заход на сайт за цифрами.
https://artificialanalysis.ai/agents/coding-agents

**Terminal-Bench / Epoch AI, разрез agent×model** — tbench.ai по умолчанию показывает только
ЛУЧШУЮ пару агент-модель (срез скрыт); но чарт Epoch AI («displays every agent-model run
submitted for a model») хранит ВСЕ прогоны — Claude Code, Codex CLI, Terminus, Goose как
обвязки поверх одной модели. Числа не извлечены (нужен интерактивный чарт), Terminal-Bench
2.0/2.1, 2026. Пересечение: **Claude Code, Codex CLI, Goose**. — ДА как источник, но нужен
ручной срез, авто-фетчем не считалось.
https://epoch.ai/benchmarks/terminal-bench · https://www.tbench.ai/

## Только как смешанные

**digitalapplied.com, «Eight Headless Coding Agents, One Task»** (22.08.2026, live-замер,
токены читались из вывода CLI, честность подтверждена: «Nothing here was estimated»). Claude
Code, Codex CLI, Antigravity CLI, Grok Build, Kimi Code, Qwen Code, Claude Code через
Z.ai-шим (GLM-5.3), Claude Code через DeepSeek-шим (V4 Flash) — 8 строк, но МОДЕЛЬ НЕ
ЗАФИКСИРОВАНА между большинством строк (каждый харнесс — свой вендорский дефолт). Полезное
внутри: 3 строки Claude Code с разными моделями — это обратный срез (харнесс фиксирован,
модель гуляет), для нашего вопроса бесполезен. Пересечение с кандидатами: **Claude Code,
Qwen Code** (только как разные строки, не как контролируемое сравнение).
https://www.digitalapplied.com/blog/headless-agent-cost-per-task-benchmark

**CORE-Bench, Opus 4.5: 42% → 78% при смене scaffold на Claude Code** (пост Sayash Kapoor,
X, вокруг arXiv 2606.26158 «Life After Benchmark Saturation», 23.06.2026). Модель
зафиксирована, харнесс — переменная, но сравниваемая пара — Claude Code против
исследовательского baseline-скаффолда CORE-Agent, а не против другого нашего кандидата.
Ценно как ДОКАЗАТЕЛЬСТВО существования эффекта харнесса (36 п.п. на одной модели), но не как
строка в нашей матрице — второй харнесс не входит в список кандидатов.
https://x.com/sayashk/status/1996334941832089732 · https://arxiv.org/pdf/2606.26158

**Vercel, «We removed 80% of our agent's tools»** (vercel.com/blog, 2026). Собственный
text-to-SQL агент d0 (не один из десяти кандидатов): 18 тулов → 1 (bash) на ТОЙ ЖЕ модели
(Opus 4.5) подняли успешность 80%→100%, токены -37…-52% (цифры расходятся между источниками),
латентность 724с→141с. Хорошая иллюстрация метода «фиксируй модель, режь тулы», но объект
измерения — не харнесс из матрицы, а внутренний прототип. Мешать нельзя.
https://vercel.com/blog/we-removed-80-percent-of-our-agents-tools

## Не годятся

**arXiv 2608.11727, «Harness-IF»** (12.08.2026). Несмотря на название, сравнивает 12
FRONTIER-МОДЕЛЕЙ в их дефолтной конфигурации по соблюдению правил из 5 «instruction
surfaces» (AP-Acc 66.1–78.6%), а не харнессы при фиксированной модели. Конкретные харнессы
из нашего списка не названы. — НЕ подходит под критерий отбора, несмотря на название.
https://arxiv.org/abs/2608.11727

**OctoBench** (arXiv 2601.10343) — заявлен как «scaffold-aware», но охват харнессов и
фиксация модели не подтверждены (реферат не даёт этого прямо, глубже не проверялось) — статус
не определён, в матрицу не включаю.

**Context-compaction gist (badlogic, 02.12.2025)** — Claude Code/Codex CLI/OpenCode/Amp:
качественное описание архитектуры компакции (пороги, промпты), БЕЗ измерений — документация
механики по чужим исходникам, не бенчмарк с цифрами.
https://gist.github.com/badlogic/cd2ef65b0697c4dbe2d13fbecb0a0a5f

## Свод: что реально можно сказать про наших кандидатов

Прямых публичных сравнений «харнесс vs харнесс» при фиксированной модели, покрывающих больше
2-3 наших десяти кандидатов одновременно, **не существует**. Из десяти кандидатов в
контролируемых (не смешанных) публикациях засветились: **Claude Code** (Systima, AA Index,
Terminal-Bench/Epoch), **opencode** (Systima, arXiv 2607.22585, AA Index, Terminal-Bench/Epoch),
**Goose** (arXiv 2607.22585, Terminal-Bench/Epoch), **Codex CLI** (Terminal-Bench/Epoch),
**pi** (Composio). Ни разу в контролируемом виде: Qwen Code, Factory Droid, Aider, Cline,
DeepSeek Harness.

Устойчиво воспроизводится один качественный вывод по трём независимым источникам (Composio,
arXiv 2607.22585, Systima): **харнесс двигает расход токенов на порядки (до 40x) при том, что
точность/успешность между харнессами на одной модели расходится всего на единицы–десятки
процентных пунктов**. То есть харнесс — это прежде всего рычаг СТОИМОСТИ, а не точности;
для оси «точность следования» из задачи публичных данных почти нет — ни один найденный
бенчмарк не измеряет соблюдение формата/правил AGENTS.md при фиксированной модели и
варьируемом харнессе (Harness-IF ближе всех по названию, но сравнивает модели, не харнессы).
Это само по себе ответ: заявленная в задаче ось «точность следования» по харнессам публично
почти не измерена — только по токенам.
