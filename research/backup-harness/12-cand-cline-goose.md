Годится с оговоркой: CLI + MCP есть по докам, но досылки нет вообще (открытый запрос),
а хуки заявлены только для macOS/Linux — на Windows-машине владельца по докам не работают.

## Чем закрывает боли владельца

- home/end: не проверено.
- блокировка главной сессии субагентом: доки говорят "параллельно", явного "не блокирует"
  утверждения нет — не измерено.
- отсутствие поля ввода у субагента: субагент документально ещё уже opencode — вообще
  read-only отчёт без MCP/edit, вопрос ввода в него не стоит так же остро, но и не решён.
- застрявший воркер игнорирует очередь: пересекается с досылкой — раз досылки нет вообще
  (открытый feature request), эта боль НЕ закрыта, по симптомам может быть хуже opencode.

## Стоимость перехода

MCP-конфиг переносится почти как есть (JSON, формат отличается по пути файла на диске).
Инжект канона через TaskStart-хук технически возможен, но заявлен только под macOS/Linux —
на Windows-машине владельца нужен WSL-обёртка или переписывание транспорта. Выгрузка
транскрипта на завершение сессии — механизм неясен по докам (TaskComplete не документирует
доступ к истории), вероятно писать самим поверх SDK/API, а не переиспользовать хук.

## Чего не проверил и почему

Живой прогон запрещён условиями задачи вне Docker, Docker не использовал (приоритет — доки).
Не читал построчно исходный код hooks-адаптера (только пересказ deepwiki, вторичный источник) —
точный payload `TaskComplete`/`TaskCancel` не подтверждён. Не проверено, блокирует ли
`use_subagents` терминал реально. TUI/home-end поведение не проверено вовсе.

Годится с оговоркой: сильнейший MCP из двух кандидатов и явные lifecycle-хуки, но ни один
хук доками не подтверждён как инжектор текста в контекст, а терминальная досылка ломает
сессию по открытым issue.

## Чем закрывает боли владельца

- home/end: не проверено.
- блокировка главной сессии субагентом: по докам НЕ блокирует по умолчанию (лучше, чем
  описанная боль на opencode) — но не подтверждено живым прогоном.
- отсутствие поля ввода у субагента: доки не описывают интерактивный ввод в подагента явно;
  вероятно так же нет, как в Cline/opencode.
- застрявший воркер игнорирует очередь: степиринг заявлен, но открытые issue показывают, что
  интерапт на середине tool-call ломает саму сессию — то есть под нагрузкой боль может
  проявиться ХУЖЕ, чем "сообщение висит в очереди".

## Стоимость перехода

MCP-сервер подключается конфигом почти без изменений. Инжект канона на старте сессии:
готового аналога SessionStart-с-инжекцией НЕТ (событие наблюдательное) — писать заново
через параметры `goose configure`/recipe system-prompt override, ждать расширения hook API
или подавать канон как часть первого user-сообщения. Выгрузка транскрипта на завершение:
`SessionEnd` отдаёт "полный контекст сессии" наблюдательно — можно повесить экспорт-скрипт
как plugin-хук, но это пишется с нуля под формат `plugin.json`, не перенос 1:1.

## Чего не проверил и почему

Живой прогон запрещён условиями задачи вне Docker, не устанавливал даже в контейнере
(приоритет — доки). Точный payload `SessionEnd`/`Stop` — из стороннего фетча goose-docs.ai
(обработано мелкой моделью), не сверено построчно с исходником aaif-goose/goose. Реальное
поведение блокировки терминала при `subagent__execute_task` и TUI home/end — не проверено.
