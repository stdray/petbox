# Сводка по кандидатам — что сходится, что расходится

Дата: 2026-09-08 | Исполнитель: Opus 5 (1M), petbox-worker-highstakes | Источники: только файлы
`01`–`20` этой папки. Ничего не запускалось, чужие файлы не правились.

## Как читать: шкала доказательности вместо слова ЗАМЕРЕНО

Легенда определяет **ЗАМЕРЕНО** как «живой прогон с записанным выводом». Файлы это растянули:
`16-cand-codex-qwen.md` переопределяет его в шапке («только чтение исходников (= ЗАМЕРЕНО в
терминах легенды)»), `13-cand-pi-aider.md` метит так чтение `docs/*.md` из установленного пакета.
Колонки «ЗАМЕРЕНО» между файлами поэтому несравнимы. Ниже — своя шкала (мой инструмент, не факт
из файлов): **A** — живой прогон с выводом; **A\*** — прогон, унаследованный из памяти/снимка и
здесь не переизмерявшийся; **B** — чтение исходников/конфигов/метаданных с указанием места;
**C** — доки, issue-трекер, сторонние пересказы; **—** — не проверено. В матрице клетка =
оценка^класс, «н/п» = ось неприменима (у продукта нет своей подписки).

## 3. Противоречия

### 3.1 droid и Task — НЕ опровержение, разные уровни

`02-snapshot.md` (карта паритета 2026-08-29, `m-38a514a2…`): «субагенту не выдаётся Task,
вложенность жёстко 1». `10-cand-droid.md`, ось «Делегирование»: «обычный (не `--mission`)
`droid exec` уже содержит инструмент `Task` в списке» — из `system/init` живого прогона.

**Прямо: это не опровержение, а разные уровни.** Снимок — про уровень 2 (что видит субагент),
инвентарь — про уровень 1 (что видит главная сессия); `10` сам дословно повторяет ограничение
снимка. Опровергнуто другое, неявное: что `Task` приходит только с `--mission`. Проверяемость
разная: уровень 1 — класс A, уровень 2 — A\* (субагента в этой волне никто не запускал).
Следствие: оркестратор→воркер работает, оркестратор→воркер→воркер — нет.

### 3.2 droid: два разных бинаря под одним именем — никем не отмечено

`10-cand-droid.md` — «Factory Droid **0.170.0**» (машина владельца), на ней отрицательный замер
досылки; `20-sandbox.md` — «droid **0.213.0**», свежая установка в Docker, на ней положительный
замер раздаваемости; `02-snapshot.md` сводит оба под заголовком «Droid (Factory), 0.170.0».
**43 минорных версии разницы**, и ни один результат не переносится на другую сборку сам собой:
«раздаваемо» доказано для 0.213.0, «досылка не работает» — для 0.170.0. Проверяется тривиально,
не проверено. Мой вывод: у владельца устаревшая сборка, часть отрицательных результатов может
быть артефактом версии, а не свойством продукта.

### 3.3 pi: что устояло, а что пало

- **Пало:** «хуков нет». `13`: API `pi.on("session_start"/"before_agent_start"/"agent_end"/
  "session_shutdown")`, где `before_agent_start` возвращает `{systemPrompt: …}` — ровно инжект.
- **Устояло, но НЕ в том объёме:** «MCP нет» — в ядре намеренно («intentionally does not include
  built-in MCP»), `mcp` не встречается в CHANGELOG до 0.85.1. Но блок «Поправка владельца»,
  дописанный в `13` уже после инвентаря, гласит: **MCP у pi подключается плагинами** (oh-my-pi) —
  то есть утверждение верно для ядра и неверно для реальной установки. Какие вербы доезжают через
  плагинный MCP — не проверял никто. Там же владелец понижает pi **не по технике, а по стоимости
  сопровождения** (своя сборка) — это решение владельца, не вывод из замеров.
- **Чего снимок не унёс:** тот же файл фиксирует, что `package.json` экспортирует `./hooks`, а
  физически `dist/core/hooks/` в 0.78.0 **отсутствует** («экспорт мёртвый»). «Хуки есть» стоит на
  доках пакета плюс противоречащий им сигнал с диска, и ни один хук не запускался — а снимок
  пишет «**Хуки ЕСТЬ**» жирным: уверенность выше той, что даёт источник (мой вывод).

### 3.4 droid и досылка: хелп против прогона

Хелп заявляет multi-turn через `--input-format stream-json`; сам CLI тут же печатает депрекейт в
пользу `stream-jsonrpc`. Прогон (`10`): 5 форм payload с `"type":"user"` → «Only 'user' messages
are accepted via stdin»; форма без `type` → хода нет (только `system/init`, exit 0); второе
сообщение в FIFO → SIGPIPE, exit 141; `stream-jsonrpc initialize` → `-32700`.
**Замер главнее доков, расхождение фиксирую.** Но объём отрицания ограничен: доказано «не
воспроизвелось ни одной из опробованных форм за отведённый бюджет», НЕ доказано «невозможно» —
схему jsonrpc подбирали вслепую. Корректно: «на 0.170.0 досылка не продемонстрирована, путь
депрекейтед, у замены нет спецификации»; «droid не умеет досылку» — сильнее данных.

### 3.5 Codex: имя переменной ключа — доки против исходника

`14-cand-others.md` (ПО ДОКАМ): «`OPENAI_API_KEY` заданный — Codex использует его и игнорирует
залогиненную ChatGPT-сессию». `16-cand-codex-qwen.md` (`login/src/auth/manager.rs:1472-1477`):
читается **`CODEX_API_KEY`**. Проверяемо второе — оно с file:line; у первого ссылки нет. Живого
прогона нет ни там ни там, `16` цитирует одну ветку — не исключено, что читаются обе. Тихо не
выбираю: для инструкции «как отдать другу» деталь решающая, снимается одним запуском.

### 3.6 «Роль≠модель сломана на двух из трёх» — цитата разошлась со смыслом

`02-snapshot.md`: «**динамическая** передача модели оркестратором сломана на двух харнессах из
трёх». `11-cand-opencode.md` цитирует эту строку как подтверждение, что у droid и pi роль и
модель вообще не разделены. Но `10`: разделены через `model:` во фронтматтере
`~/.factory/droids/<role>.md`; `13`: разделены — роль = extension/agent-файл, модель — флаг.
Снимается уточнением, которое `11` потерял: снимок про **динамическую** передачу (выбор модели
в момент спавна), инвентари — про **статическую** (правка YAML); на droid динамический путь
`--worker-model` как раз требует auth. Динамика доказана в коде только у Codex (per-spawn `model`)
и Qwen (`SubagentConfig.model` = `authType:model-id`, даже другой провайдер на роль).

### 3.7 Короткие расхождения

- **Aider: позиционирование против метаданных.** README — «самый стабильный terminal+git-native»,
  ~15B токенов/неделю; метаданные — `pushed_at` 2026-05-22 (3.5 мес без пушей), тег v0.86.0 от
  2025-08-09 (>года), 1856 issue. Проверяемы метаданные, не цифры вендора: «живость под вопросом».
- **Слово ЗАМЕРЕНО разошлось на три смысла** (см. «Как читать»): иначе Codex (ни одного запуска)
  и droid (Docker-прогон с exit-кодами) встанут в таблице равными.
- **Qwen Code ≠ Gemini CLI, хотя форк.** `14`: у Gemini CLI `SessionEnd` транскрипт не передаёт;
  `16` по коду: у Qwen `transcript_path` заполняется для ВСЕХ событий — выводы не переносятся.
- **Снимок сам себя отменяет.** В `02-snapshot.md` соседствуют ранний вывод «граница проходит ПО
  МОДЕЛИ, а не по режиму» и поздний «отменяющий прежний: и по режиму тоже» — ранняя формулировка
  всё ещё в тексте и цитируется по ошибке.

### 3.8 Cline и Goose: авторская оговорка сильнее их плюсов

`12` сам помечает источники как вторичные. Значит их лучшие свойства — Goose «не блокирует главную
сессию», Cline «TaskStart = аналог SessionStart» — стоят на слабейшем классе во всей папке и не
перевешивают доказанное по коду у Codex/Qwen. Отдельно: хуки Cline заявлены **только для
macOS/Linux**, машина владельца — Windows.

### 3.9 DeepSeek dsh: лучший результат при худшем доказательстве

`15` пишет, что по боли «нет поля ввода у субагента» dsh «закрывает лучше всех кандидатов на
сегодня»; источник — одна строка README про `tool-subagent-control`. При этом: ноль прогонов,
MCP-пакета не найдено (отсутствие не доказано — code search упёрся в rate-limit), Issues отключены,
16 версий за 4 недели, README обещает ломающие изменения. Парадокс роли (мой вывод): часть силы
dsh — пакеты `subagent-claude-code`/`subagent-codex`, вызов ЧУЖИХ харнессов; для «запасного на
случай, когда Claude Code недоступен» эта фича бесполезна.

## 4. Кто закрывает главную боль: досылка в ЗАСТРЯВШЕГО воркера

Боль точная: воркер встрял **внутри** зависшего теста (внутри tool-call), сообщение в очереди, главная сессия ждёт. Критерий — доходит ли сообщение, когда следующая «безопасная граница» не наступает вовсе.

| кандидат | механизм | доходит ли до застрявшего внутри tool-call | класс |
|---|---|---|---|
| **Codex CLI** | `send_input(target, message, interrupt)`: `true` — немедленно, `false` — в очередь; `wait_agent` досрочно завершается при новом вводе | **Да по семантике: единственный с явным немедленным прерыванием**, не привязанным к границе | B (живьём не гонялось) |
| **Qwen Code** | `send_message`+`task_id`: running → «at the next tool-round boundary», paused → как первая инструкция продолжения | Нет: граница у застрявшего не наступает; для *paused* — да | B |
| **pi** | `steer`: «delivered after the current assistant turn finishes its tool calls» | Нет по той же причине — **тот же класс, что у opencode** | C/B |
| **DeepSeek dsh** | `tool-subagent-control`: messaging + **interrupt** + listing | Потенциально да, но ноль прогонов и alpha | C |
| **Goose** | Enter/Ctrl+C во время обработки | Скорее ломает: #1624/#3978 — прерывание в tool-call рушит сессию | C (отриц.) |
| **opencode** | steer «в следующей безопасной точке»; форс закрыт `not_planned` (#24298, #16102) | Нет — это и есть исходная боль | C |
| **droid** | `stream-json` / `stream-jsonrpc` | Не продемонстрировано ни одним путём | **A (отриц.)** |
| **Cline** | механизма нет, открытый FR без ответа мейнтейнеров | Нет | C |
| **Aider** | неприменимо: нет субагентов, синхронный REPL | Нет | C |

**Мой вывод, а не замер:** кандидаты делятся не на «есть досылка / нет», а на «доставка на
границе» и «доставка с прерыванием»; почти все «есть» — первого типа, а граница у застрявшего
воркера не наступает. Следствие: формулировка `02-snapshot.md` «pi — прямое попадание в главную
боль владельца» **не выдерживает чтения самой цитаты из `13`** — механизм pi того же класса, что
уже не устроил владельца в opencode. Явный `interrupt` — только у Codex (по коду) и dsh (README).

## 5. Что осталось непроверенным — по влиянию на решение

1. **Сценарий главной боли не воспроизведён НИ У КОГО**: никто не запускал зависший внутри
   tool-call воркер и не пытался достучаться, все «закрывает» — из семантики кода или README.
   Без этого замера выбирать нельзя: он ранжирует по той оси, ради которой всё затеяно.
2. **Раздаваемость на чистой машине измерена только у droid** (`20-sandbox.md`); легенда требует
   именно чистую машину, у Codex/Qwen вывод по коду, у остальных по докам.
3. **Имя env-переменной у Codex** (3.5): снимается одним запуском, без него инструкция другу может не сработать.
4. **PetBox-обвязка живьём не проверена ни у одного нового кандидата**: у Codex/Qwen прочитан
   контракт хуков, но наш `hooks.json` и MCP к ним не подключали; у droid «1:1» — класс A\*.
5. **Разрыв версий droid 0.170 vs 0.213** (3.2): вывод по досылке не перепроверен на свежей сборке.
6. **TUI-гигиена (home/end) не проверена живым нажатием ни у кого** — включая opencode (текст
   `keybinds.mdx`) и pi (`docs/keybindings.md`): ежедневный раздражитель владельца с нулевой
   доказательной базой.
7. **pi: мёртвый экспорт `./hooks`** в 0.78.0, несовместимость примера `subagent` и — по поправке
   владельца — какие вербы реально доезжают через плагинный MCP (oh-my-pi): всё это не проверялось.
8. **DeepSeek dsh: ноль прогонов**; отсутствие MCP не доказано (rate-limit), `SAFETY.md` не читан.
9. **Cline/Goose: только вторичные источники**; правда ли хуки Cline не работают на Windows (это
