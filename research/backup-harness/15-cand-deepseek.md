## Чем закрывает боли владельца

- home/end листает историю — не проверено (нет живого запуска Web UI/TUI).
- блокировка главной сессии субагентом — ПО ДОКАМ закрывает: `subagent`-контракт описан как
  асинхронный (continuable children, discovery живых/сохранённых детей), но факт неблокирования
  не измерен.
- нет поля ввода у субагента — ПО ДОКАМ закрывает лучше всех кандидатов на сегодня:
  `tool-subagent-control` прямо называет "adjacent-Agent messaging" как модель-доступную
  возможность, т.е. с ребёнком можно переписываться, а не только ждать финала.
- застрявший воркер игнорирует очередь — та же возможность (interrupt) потенциально решает,
  но без прогона зависшего теста утверждать нельзя.

## Стоимость перехода

Писать заново: (1) MCP-клиент/сервер-адаптер — в дереве пакетов такого пакета нет, значит
подключение PetBox MCP-сервера либо через будущий community-плагин (`dsh-plugin` topic на
GitHub существует как механизм расширения, но конкретного MCP-плагина не нашёл), либо
самостоятельный `dsh`-плагин под `ctx.tools`/`ctx.llm`-подобный сервис. (2) Формат транскрипта
для выгрузки на Stop — своя схема session log (JSONL, `SESSION_FORMAT_VERSION`, `session-log-deepseek`
как пример "upload incremental log as request metadata") отличается от Claude Code transcript
formatа, нужен конвертер. Переносится почти бесплатно: сам SessionStart/Stop-хук вызов — если
наш `hooks.json` написан в формате Claude Code, `hooks-claude-code`-бридж должен запустить его
без переписывания (заявлено, не проверено).

## Идеи (отдельно от вердикта по годности)

Каждая идея — один тезис: в чём она и применима ли к PetBox (MCP-сервер, роли с прибитыми
моделями, инжект канона на старте, выгрузка транскрипта на стоп).

- **"Всё — плагин", включая agent-loop и sandbox.** Расширяемость не через API поверх
  фиксированного ядра, а через замену любого сервиса в `cordis.yml`. Применимо к PetBox
  частично: у нас role↔model уже прибиты жёстко намеренно (это наш инвариант, не то, что
  стоит "расплагинивать"), но сама идея "инжект канона = плагин на `session/start`-событие,
  переключаемый без правки ядра" — переносима как паттерн организации нашего хука.
- **Capability seam = Service Definition + Provider + Consumer, обязательно втроём.** Явно
  раздельные роли для "что это", "кто это делает", "кто это использует" — не даёт смешать
  контракт с реализацией. Применимо: наш MCP-сервер уже играет роль Provider для внешнего
  Consumer (харнесса); полезно как словарь для документации схемы, не как код для переноса.
- **Hook-бридж запускает ЧУЖОЙ `hooks.json` без переписывания, через общий `hook-protocol`.**
  Идея — не "портировать хуки", а "эмулировать протокол другого харнесса как плагин". Прямо
  применимо к PetBox: если писать dsh-плагин, эмулирующий Claude Code hook-протокол, наш
  существующий SessionStart/Stop-хук заработает без изменений на стороне PetBox.
- **Delegation seam с одним контрактом `ctx.subagents` на любой backend** (in-process fresh,
  in-process forked-от-истории, ACP, реальный Codex, реальный Claude Code, реальный dsh по SDK).
  Идея — единая точка входа делегирования независимо от того, "свой" это агент или внешний
  бинарник. Применимо к PetBox напрямую: сегодня схема оркестратор-воркеры у владельца — это
  обычная сессия Claude Code; идея форк-от-истории (child, засеянный завершённой историей
  родителя, а не с нуля) закрывает нашу же боль экономии контекста при повторных вызовах.
- **`tool-subagent-control` — messaging/interrupt/listing к живому ребёнку как модель-доступный
  инструмент**, а не служебная админ-команда. Это прямое решение боли владельца "воркер встрял,
  досылка невозможна" на opencode — если работает, это лучшая находка файла. Применимо к
  PetBox как референс-архитектура для собственной досылки, даже если сам dsh брать рано.
- **Session log как единственный источник истины для всего, что видела модель** ("model-visible
  ⟺ logged", инвариант из AGENTS.md) — любой контекст, дошедший до модели, обязан быть
  реконструируем из лога. Применимо к PetBox: наша выгрузка транскрипта на Stop выиграла бы от
  такого же инварианта — сейчас неясно, гарантированно ли canon-инжект виден в выгружаемом
  транскрипте.
