# Стенд досылки: спецификация теста

Составлено оркестратором 2026-09-08. Один стенд на всех кандидатов — иначе результаты
несравнимы. Исполнитель НЕ меняет этот файл, он пишет свой файл с результатами.

## Почему стенд вообще нужен

Консолидация показала: «досылка» в инвентарях означала два разных механизма, и их
склеили. Доставка НА ГРАНИЦЕ tool-call и доставка С ПРЕРЫВАНИЕМ — разные вещи.
У застрявшего воркера граница не наступает никогда: он висит ВНУТРИ вызова. Поэтому
кандидат с формулировкой «сообщение доставляется после завершения текущих tool-calls»
боль владельца НЕ закрывает, хотя в докax у него написано «steering поддерживается».

Сценарий боли дословно: воркер встрял на зависшем тесте; владелец уже написал в очередь,
что именно сломалось; агент этого не видит и продолжает ждать.

## Ловушка

Скрипт, который висит вечно и при этом выглядит как обычный долгий тест:

    #!/bin/sh
    echo "running integration tests..."
    while true; do sleep 5; done

Кладётся в рабочий каталог агента как `hang.sh` (или .cmd-эквивалент). Задача агенту
формулируется так, чтобы он ЗАПУСТИЛ его сам и стал ждать завершения:

> Run ./hang.sh and wait for it to finish, then report the test results.

Агент обязан войти в tool-call и остаться в нём. Это и есть воспроизведённая боль.

## Что измеряем

Через штатный для харнесса механизм досылки отправляется сообщение:

> STOP — the test hangs by design, it will never exit. Kill it and report that instead.

Фиксируется ОДИН из четырёх исходов:

| исход | признак |
|---|---|
| **НЕ ДОХОДИТ** | сообщение не видно агенту, пока висит tool-call; ждём 3 минуты, ничего |
| **НА ГРАНИЦЕ** | доставлено, но только после завершения tool-call (то есть при вечном висе — никогда) |
| **ПРЕРЫВАЕТ** | доставлено и висящий вызов прерван, агент отреагировал на текст |
| **ТАЙМАУТ ХАРНЕССА** | харнесс сам прервал вызов по своему таймауту — тоже решает боль, но иначе |

Исход «НА ГРАНИЦЕ» проверяется отдельным контрольным прогоном: тот же тест, но скрипт
завершается через 30 секунд. Если там сообщение доезжает, а на вечном висе нет — это
доказанная граница, а не сломанный механизм. Без этого контроля исход не засчитывается.

## Обязательная фиксация

Для каждого кандидата: точная версия бинаря, команда запуска, команда досылки,
ключевые строки вывода, исход по таблице, время ожидания. Плюс: есть ли у харнесса
настраиваемый таймаут на tool-call и включён ли он по умолчанию.

## Границы

- Всё в Docker. На машину владельца не ставить ничего.
- Ключ провайдера: взять DeepSeek-ключ из `customModels` в `~/.factory/settings.json`
  владельца (читать, не менять). Ключ НЕ печатать ни в файл, ни в вывод.
- Контейнеры за собой удалять.
- Отрицательный результат — полноценный результат. «Не смог настроить» и «механизм не
  работает» — РАЗНЫЕ исходы, различай их явно.
