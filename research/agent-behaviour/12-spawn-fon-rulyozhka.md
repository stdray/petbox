## Ось 2 по харнессам: спавн → fg/bg → результат

**Claude Code** — два слоя. (a) CLI `Task` (`claude.exe`, `29-cand-claude-code.md §6,9`):
синхронен для хода, длинные вызовы фактически уходят в фон [код, строки бинаря]. (б) SDK
`Agent`-тул этой сессии: в схеме **нет параметра fg/bg вовсе** — решение не экспонируется
модели (в отличие от `Bash.run_in_background`) [код, схема тула, 10.09]. Родитель не
блокируется — наблюдал сам на фоновых Bash этого хода, владелец подтвердил то же для
субагентов первым лицом. Результат — push-нотификация в следующем ходе, не инлайн.
`[НЕПРОВЕРЕНО]`: скрытый forced-foreground вне схемы.

**qwen 0.23.2** — `backgroundRequested` [код, `chunk-4F7GQGXB.js:76444`, установлен
локально, 10.09]: fork+non-interactive → true; иначе явный `run_in_background`, иначе
`!fork && working_dir===void 0 && name===void 0`. `working_dir`+фон → жёсткий отказ
валидации (`:76449-76452`): «caller owns the worktree and could remove it while the
detached agent is still running». Результат — push, «completion notification»
[код, `agent.ts:856-873`, via `16-cand-codex-qwen.md`].

**opencode 1.18.29, БЕЗ флага** — строго блокирующий: REST-ответ на параллельный вопрос
вернулся только через 1.15с ПОСЛЕ завершения task-tool; TUI-текст, набранный при живом
воркере, обработан только после его конца [замер 08.09, `32-bench-opencode.md`]. Своё
описание тула обещает push-нотификацию, но `background` в схеме тула НЕТ — обещание не
подтверждено. **С флагом — см. раздел ниже, это готовый замер, не плейсхолдер.**

**codex 0.153.4** — `spawn_agent` возвращает `agent_id` сразу [код, репо-клон 08.09,
`multi_agents_spec.rs:390-399`]. Результат — **pull**: отдельный `wait_agent`, не
push-нотификация. **[НЕПРОВЕРЕНО]**: есть ли push-путь без опроса — не нашёл.

## opencode + `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true` — готовый замер (параллельный агент, 10.09)
Стенд: одноразовый репозиторий, живая DeepSeek-модель, флаг per-invocation, конфиги не
трогались.

| ячейка | спан tool-call | ребёнок | фон? |
|---|---|---|---|
| флаг ON, `background:true`, разовый `run` | 13мс | 75с | да |
| флаг OFF, без параметра | 79005мс | 75с | нет |
| флаг ON, `--attach` к `serve` | 12мс | 75с | да |
| 3 параллельных в одном ходе | 9–12мс каждый | 20с | да, все параллельно |

**Решающий пункт — родитель доступен, пока ребёнок работает: ДА, подтверждено.** На
персистентном сервере (`--attach`, `ses_f74986e32ffe2appysVDz6G8yK`): ход 1 запустил
75с-ребёнка; ход 2, отправленный на ~22с работы ребёнка, задал несвязанный вопрос
(«6×7») и получил ответ за 2.86с, exit 0 — за ~52с ДО конца ребёнка. Оговорка: реальные
TUI-нажатия НЕ наблюдались (winpty недоступен; фон убит харнессом на второй попытке) —
`--attach` это прокси того же client/server-механизма, не TUI-наблюдение.

**Возврат результата — реален.** Через ~79с в сессию push-инжектится синтетическое
`role:"user"` сообщение `<task id=jobId state="completed"><task_result>…</task_result>`,
`id` = jobId спавна; агент сам продолжает ход без действия пользователя. Подтверждено на
3 параллельных.

**Нюансы, решающая часть находки:**
1. **Фоновый ребёнок молча убивается при выходе родительского процесса.** Голый
   `opencode run` (без `--attach`) печатает «you will be notified automatically», сам
   выходит за ~5.8с, ребёнок абортится через ~2.7с (`MessageAbortedError`) — сессия больше
   не обновляется (проверено спустя 8 мин). Безопасно только под долгоживущим
   TUI/attached-сервером. Тот же класс тихого отказа, что уже фиксировался в папке
   (отчёт «успех», работа мертва).
2. **Отмена не работает.** `POST /api/session/{jobId}/interrupt` → 204, но job не
   останавливается — 60с-ребёнок «прерванный» всё равно завершился штатно в 64с; других
   cancel-эндпоинтов в OpenAPI нет.
3. Параллельность: 3 без проблем, свыше — `[НЕПРОВЕРЕНО]`.
4. Отдельный рычаг: `POST /experimental/session/{id}/background` — detach уже блокирующих
   субагентов постфактум, отличается от спавн-параметра.
5. **Необъяснённая хрупкость**: сессия через голый `POST /api/session`+`/prompt` — БЕЗ
   тула `task`; та же сессия через `opencode run --attach` — тул есть. Не раскопано.
6. `opencode serve` требует HTTP Basic, пароль только через `OPENCODE_SERVER_PASSWORD`.

## Что отсюда следует
Критерию владельца отвечают ЧЕТЫРЕ харнесса, не два: Claude Code (SDK, push, без ручки
fg/bg), qwen (рецепт E), И opencode — но ТОЛЬКО под `--attach` к живому `serve` с флагом,
не в разовом `run` (там тихая смерть при выходе процесса) и без живого TUI-подтверждения.
codex даёт фон через pull, не push — иной, не худший ответ. У opencode `interrupt`
не работает вовсе — по отмене он не лучше codex.
