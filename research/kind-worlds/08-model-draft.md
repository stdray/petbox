# 08 — Синтез-черновик модели (то, что проверяем)

Дата: 2026-08-26. Собрано оркестратором из `07a-design-minimal.md`, `07b-design-predicate.md`
и `07c-design-comparison.md`.

> **Это НЕ решение и не спека.** Это единая модель, против которой идёт проверка фактами.
> Нужна затем, чтобы четыре проверяющих работали с одной моделью, а не с четырьмя своими.
> Всё, что она не выдержит, — результат, а не провал.

---

## Понятия

Правило именования: EN (в код) / RU (обсуждать). Один термин — один референт.

| EN | RU | Что это |
|---|---|---|
| **Unit** | единица | запись: текст, поля, метки, связи, коммиты, родитель |
| **Board** | доска | именованная группа единиц, живущая по одному набору правил |
| **State** | состояние | позиция единицы; **class объявляется**: `open` / `done` / `dropped` |
| **Transition** | переход | разрешённая смена состояния. **Создание единицы = переход из `*new*`** |
| **Condition** | условие | конъюнкция атомов из ЗАКРЫТОГО набора; висит на переходе |
| **Effect** | действие | запись на переходе; словарь из одного глагола `move` |
| **Link** | связь | именованная типизированная ссылка единица→единица |
| **Summary** | сводка | вычисление над связями; фиксированные агрегаторы |
| **Preset** | заготовка | копируемое описание, разворачивается одним действием |

## Условия — закрытый набор атомов

```
condition = atom*                       # список = И. Дизъюнкция — под вопросом, см. ниже
atom      = bring | have | field
bring     = signature(by) | note | artifact(kind) | checklist(name)
have      = селектор связей: rel, направление, тип цели, state/class цели, count-сравнение
field     = поле этой единицы: имя, оператор, константа
```

**Произвольного языка предикатов НЕТ** — это отклонили оба проектировщика независимо.
Расширение — новым родом атома, а не открытием выражений. Правило роста: новый атом только
после двух независимых процессов, которым он понадобился.

## Что уже решено этим черновиком

| решение | почему |
|---|---|
| class состояния **объявляется**, не выводится | Р-13: на `client-issues` статус `Done` имеет исходящие переходы; вывод дал бы «не терминальный» |
| создание = переход из `*new*` | оба дизайна независимо; сворачивает link-констрейнты и условия перехода в одну сущность |
| граница обобщения — между чтением и записью | condition читает, effect пишет; иначе получаем программу |
| ролей нет, есть только `owner` | ограничение владельца, см. `07-requirements.md` §6 |

## Что ОСТАЁТСЯ РАЗВИЛКОЙ — проверять обе ветки

### Развилка 1 (Р-11): где живут правила

- **(a)** на доске; объекта-владельца нет; «процесс» эмерджентен — кластер сцеплённых досок;
- **(b)** отдельный `Blueprint` (чертёж), доска на него ссылается; процесс адресуем.

Владелец читает процесс как **контейнер**, внутри которого живут связи, — это ближе к (b).
Существенно: (b) НЕ воспроизводит сегодняшнюю болезнь, потому что чертёж не выбирается
членством и конкурирующих источников правил не образует.

### Развилка 2 (Р-12): признак «сервер проверяет / держится честностью»

- **(a)** флага НЕТ: носитель правила и есть маркер — данные всегда проверяет сервер,
  проза в памятке всегда держится честностью;
- **(b)** `enforce: server | honor` — обязательный атрибут каждого атома.

## Заведомо не проработано

- **Миграция** — обоим проектировщикам было запрещено думать про совместимость.
- **Артефакты и комментарии как хранилище** — где физически живут, чем адресуются.
- **Роли шире `owner`** — намеренно вне рамок (см. `07-requirements.md` §6).
- **Устойчивость имён** — что происходит с агентами при переименовании состояний.
