### Что решено данными, а не вкусом

- **Где живут правила → отдельный `Blueprint`** (доска на него ссылается). Живой quartet уже
  единый кросс-kind документ; вариант «правила на доске» проигрывает.
- **Флаг enforce → вариант (c), урезанный.** Условия делятся на **identity** («кто ты») и
  **evidence** («что предъявил») — это выживает. Идея «вывести принуждение из семейства и
  убрать настройку» — **отклонена владельцем дважды**, не повторять:
  - однородность живой конфигурации (7 из 7 honor) — **состояние данных, а не свойство
    модели**; per-transition гранулярность обязана остаться, это конфигурируемое поведение
    конструктора процесса («могу захотеть вернуть ручной перевод idea review→approved»;
    «backlog→todo только руками, как при формировании спринта»);
  - более того, пара `requiresApproval` + `enforceApproval` — **тень отсутствующей модели
    ролей**: два поля кодируют один бит, потому что сказать «двигать могут owner и
    dev-agent» нечем. Когда роли появятся, оба поля схлопнутся в «множество акторов,
    которым разрешён переход». Сейчас роли НЕ проектируем (правило отсечения), но дизайн
    не должен жёстко зашивать «одобрение = булев флаг».
- **Артефакты → ничего не строим.** 0 из 7 сценариев требуют нового механизма. git-lfs и S3
  отклонены; условия возврата записаны в `09d`.
- **Класс состояния объявляется, не выводится** — на `client-issues` статус `Done` имеет
  исходящие переходы, вывод дал бы «не терминальный».
- **Закрытие процесса** — это частный случай ПЕРЕНОСА досок между процессами. Требования
  владельца: узлы остаются доступными; конфликта двух методологий во время работы нет.

### Ограничения, нарушать нельзя

- **Правило отсечения:** предложение, которое усложняет по сравнению с текущей реализацией,
  в обдумывание не берём — фиксируем фактом и идём дальше.
- **Ролей нет, есть только `owner`.** Не обобщать субъекта. Модель прав системы и модель
  ролей методологии — разные вещи (решение владельца).
- **Переименование состояний дорого:** 9 поведенческих мест, все вне документа правил;
  худшее — `AGENTS.md`, инжектируется в начало каждой сессии. Имена ПОНЯТИЙ менять дёшево,
  имена СОСТОЯНИЙ — нет.
- **Терминология:** английский термин, русский рядом. Метафор-самоделок не заводить
  (слово «мир» уже отклонено владельцем).
- Никакого рынка, конкурентов, денег, сравнений с Linear/Jira — только техническая и
  пользовательская сторона.

### Как работать

Гейты: `./build.ps1 -Target Test` И ОТДЕЛЬНО `dotnet run scripts/inspect-gate.cs` —
второй hook-only, зелёный Cake про него не доказывает ничего. Деплой: push `main`, затем
`git tag -f deploy && git push origin deploy --force`; проверять против живого
`GET https://petbox.3po.su/version` → `shortSha`, а не против `gh run watch`.

Песочница `kind-resolution-lab` (проект с флагом sandbox, ключ `sandboxOnly`, TTL до
2026-09-02) содержит живые репродукции: застрявший узел `n1`, дефект сообщения
`board_create`. Ключ в MCP-конфиге в скретчпаде прошлой сессии; если протух — выпустить
новый через `apikey_create(sandboxOnly:true)`.
