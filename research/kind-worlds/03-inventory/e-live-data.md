Дата: 2026-08-26. Истина: origin/main 4d956ad5 (сервер /version совпадает). Автор: petbox-worker.

## Что это за область

Не код — то, что реально лежит на сервере: инвентарь `$system` (доски, инстансы, каталог
kinds, коллизии слагов), фактическое состояние песочницы `kind-resolution-lab`, и честная
граница знания по остальным 9 проектам workspace `stdray` + `petsonde`. Код — три соседних
инвентаря, сюда не входит.

## Факты — `$system` (сессионный ключ, проверено `tasks_board_list/methodology_list/rules_get`)

8 досок, membership явный у всех (легаси-null нет): `classic`(kind classic,`$utility`),
`client-issues`(simple,`$utility`), `ideas`/`intake`/`spec`/`work`(quartet), `roadmap`
(simple,`$utility`,закрыта), `wiki`(wiki,`$utility`). Инстансы: `quartet`(открыт,v22) +
`smoke-classic-818`/`smoke-clone-818`/`smoke-verdict-gate`(закрыты, **0 досок каждый** →
живых узлов на досках закрытых инстансов нет).

Каталог kinds — объединение ВСЕХ документов правил (не только видимых доскам):

| kind | документы (версия) | идентичны? | авторитетна для живой доски |
|---|---|---|---|
| `wiki` | утилита(v2), `quartet`(v22) | да, побайтово (page: draft/live/promoted/stale, 7 переходов) | утилита — доска `wiki` в `$utility` |
| kind доски `classic` | не объявлен нигде живом | — | builtin-пресет `classic` (fallback) |
| kind доски `simple` | не объявлен нигде живом | — | builtin-пресет `simple` (fallback) |

| `ideas` | `quartet`(v22), `smoke-verdict-gate`(v21,закрыт) | нет — verdict-gate без статуса `shipped`, с verdict-артефактами | `quartet` — доска `ideas` |
| `spec` | `quartet`(v22), `smoke-verdict-gate`(v21,закрыт) | нет — verdict-gate добавляет verdict-артефакт, без `delivery` | `quartet` — доска `spec` |
| `work` | `quartet`(v22), `smoke-verdict-gate`(v21,закрыт) | нет — verdict-gate добавляет статус `Deferred` + verdict-артефакты | `quartet` — доска `work` |

живой доски задевает только `wiki`. `classic`(kind-в-документе) и kind доски `classic`
(fallback) — разные вещи, не путать: живая доска `classic` их не видит вовсе.

## Факты — песочница `kind-resolution-lab` (sandboxOnly ключ, `lab-mcp.json`, JSON-RPC)

Фактическое состояние на 2026-08-26 (после снимка, снимок **устарел**):

- инстансы: `classic`(закрыт,v3,board `classic` закрыта), `alt`(закрыт,v6,boards `alt-classic`
  закрыта + `alt-wiki` закрыта), `probe2`(открыт,v7,board `probe2`), **`alt2`(открыт,v5,board
  `alt2`, kind `simple`) — в снимке не упомянут вовсе**.
- доски: `wiki`(`$utility`,open,узел `probe`:page/draft), **`wiki2`(`$utility`,open — НЕ
  зомби, см. Противоречия)**, `alt-classic`/`alt-wiki`/`classic`(закрыты), `alt2`/`probe2`(open).
- зомби-досок сейчас нет: у обоих закрытых инстансов (`classic`,`alt`) все их доски тоже закрыты.
- узел `n1` (board `wiki2`, type `note`, status `final`, v2) — застрял: `wiki2` резолвится
  через `$utility`, чей kind `wiki` знает только type `page` / статусы draft-live-promoted-
  stale; ни type `note`, ни status `final` там не существуют. `note`/`rough→final` — это
  ровно kind `wiki` инстансов `alt`/`classic` (идентичны друг другу), под которым `n1`,
  видимо, и был создан до переноса доски в `$utility`. Тип иммутабелен → узел нечитаем по
  текущим правилам необратимо. Эталон подтверждён эмпирически, не со слов.
- kind `classic`(в документах `alt`/`classic`) — идентичны, builtin-пресет. kind `simple`
  (в `alt2`/`probe2`) — не сверял побайтово, не проверено.

## Что владелец должен снять своим ключом (чтобы цена C стала точной)

На каждый из 9 проектов (8 боевых + `petsonde`), пять вызовов:
`tasks_board_list` (kind+membership+legacy-null доски) → `tasks_methodology_list` (инстансы,
открыт/закрыт, их kinds/boards) → `tasks_methodology_utility_get` (утилитарный слой, если
есть) → `tasks_methodology_rules_get(key)` на каждый найденный инстанс (закрытые включительно)
→ `tasks_search(statusKind:[open,terminalok,terminalcancel], bodyLen:0)` по каждой доске
закрытого инстанса (искать живые/застрявшие узлы). Из документов построить тот же каталог
kinds и отметить коллизии слагов, как сделано выше для `$system`. Это ~45 дешёвых вызовов,
не «аудит» в общем смысле.

## Где модель протекает

- Закрытие инстанса не освобождает и не помечает его kind-слаги: `smoke-verdict-gate` и два
  `smoke-classic-*` в `$system` держат 5 из 6 живых коллизий, невидимых снимку именно потому,
  что ни одна их доска не открыта — коллизия существует в данных, но не в текущем резолвинге.
- Перенос доски между инстансами (`wiki2`: `alt`/`classic` → `$utility`) не проверяет и не
  мигрирует типы/статусы существующих узлов — источник `n1`, воспроизведён вживую в песочнице.
- "Зомби" не является залипающим состоянием: `wiki2` перестал быть зомби простой сменой
  `methodologyInstance`, без видимого шага миграции для уже застрявшего узла.

## Противоречия

- `02-snapshot.md` (со слов аудита `kind-worlds-model-audit`): «одна коллизия — kind `wiki`».
  Полный каталог документов правил $system даёт 6 коллизий слагов; снимок был ограничен
  видимыми живым доскам, не является ошибкой, но задаёт менее полную базу для цены C.
- `02-snapshot.md`: «доска `wiki2` — зомби: открыта, инстанс закрыт, правила заморожены».
  На момент проверки `wiki2.methodologyInstance == "$utility"` (всегда открыт) — зомби-статуса
  нет. Снимок устарел (сам предупреждал об этом), как и отсутствие инстанса `alt2` в нём.
- Узел `probe` (board `wiki`) снимком не упомянут — не противоречие, просто не описан.

## Что умрёт под целью C

- Верб «объявить kind внутри инстанса» (`tasks_methodology_rules_upsert` с `kinds[]`) как
  единственный путь — вместе с ним умирает сама возможность нескольких копий одного слага
  по инстансам одного проекта (все 6 найденных коллизий в `$system` устроены только потому,
  что kind живёт в инстансе/утилите, а не в проекте).
- Необходимость вручную сверять `rules_get` каждого инстанса на предмет дублей — заменяется
  единым каталогом.
