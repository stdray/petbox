# 07b — Дизайн с нуля: единый язык условий (ветка «гипотеза показана»)

2026-08-26. Вход: `07-requirements.md` (весь), `01b-evolution.md`, `01-legend.md` A–B; реализация не читалась.

**Ядро.** Всё в системе — Unit на Board. У Unit есть State; смена State — Transition,
включая рождение единицы (переход из псевдосостояния `*new*`). На переходе висят Guard —
условие на закрытом языке из трёх атомов — и, отдельно, Effects из фиксированного
словаря записей. Всё описывает один документ — Blueprint.

## 1. Понятия

| EN | RU | Что это |
|---|---|---|
| Unit | единица | запись: текст, поля, метки, связи, привязка к коммитам |
| Board | доска | именованная группа единиц, живущая по одному Blueprint |
| Blueprint | чертёж | документ: типы единиц, состояния, переходы, условия, действия, сводки |
| State | состояние | позиция единицы; несёт class: `open` / `done` / `dropped` |
| Transition | переход | разрешённая смена состояния; создание = переход из `*new*` |
| Guard | условие | предикат перехода: список требований-атомов (§2) |
| Evidence | свидетельство | предъявляемое переходу: `signature` / `note` / `artifact` / `checklist` |
| Link | связь | именованная типизированная ссылка между единицами |
| Effect | действие | запись на переходе; словарь из одного глагола `move` |
| Summary | сводка | постоянное вычисление над связями (селекторы те же, что в Guard) |
| Preset | заготовка | сохранённый Blueprint; новый процесс — одним копированием |

Гигиена: один термин — один референт; слов `kind`, `instance`, `world` в модели нет. Производные
(не понятия): вложенность = `part-of`; приоритет/метки = поля; class выводится из чертежа;
«процесс» и «цепочка» — рисунок связей и условий рождения (§4).

## 2. Язык Guard: три атома, одна связка, обязательный сторож

```
guard   = atom*  |  any(atom*)        # список = И; any = ИЛИ (редкий, линтер ворчит)
atom    = bring | have | field        # каждый атом обязан нести enforce
bring   = свидетельство: what (+ by: owner | artifact_kind: K | checklist: имя)
have    = селектор связей: rel, направление, тип цели, state/class цели, count-сравнение
field   = поле этой единицы: имя, оператор (= != in), константа
enforce = server (сервер блокирует) | honor (держится честностью агента)
```

Нотация — структура данных (YAML/JSON, атомы в духе JSONLogic), не строковый DSL:
валидация при сохранении, адресные ошибки. Пропущенный `enforce` — ошибка сохранения.

## 3. Четыре наблюдённых условия — один механизм

```yaml
review -> accepted:
  guard:
    - {bring: signature, by: owner,          enforce: server}  # одобрение человеком
    - {bring: note,                          enforce: honor }  # письменное обоснование
    - {bring: artifact,  artifact_kind: spec_plan, enforce: server}  # артефакт рода K
    - {bring: checklist, checklist: dor,     enforce: honor }  # пройденный чеклист
```

Разница между условиями — вид свидетельства и сторож; четыре былых поля — четыре значения атома `bring`.

## 4. Докуда дотягивается обобщение

- **Ограничение на создание** — да, целиком: создание — обычный переход из `*new*`,
  обязательная ссылка — атом `have` на нём (пример в §8а, тип `contract`).
- **Ограничение прав (треб. 11)** — да, как измерение: `enforce` обязателен на каждом
  атоме, разница server/honor видна в каждой строке текста правил (§7); «кто сторожит»
  отделено от «что требуется» по построению.
- **Сводки (треб. 6)** — наполовину: селекторы те же (`have`), исполнитель другой
  (постоянно, не в момент перехода); агрегаторы фиксированы (`count`/`all`/`fraction`)
  плюс единственный подъём `lift: part-of`. Guard НЕ ссылается на Summary (запрет
  сцепления, §5): «закрыть, когда все части закрыты» — прямой атом `have`.
- **Действия на переходе (треб. 4)** — нет, принципиально: Guard читает, Effect пишет;
  втянуть записи в язык условий — получить программу. Effects переиспользуют только
  селектор `have` и знают один глагол `move: <селектор> -> <state>`. Каскад ограничен
  статически: server-атомы на целевом переходе — чертёж невалиден при сохранении.

## 5. Граница обобщения — явно

В языке НЕТ и не должно появиться: переменных; пользовательских функций и агрегаторов;
рекурсии (подъём по `part-of` — единственная, встроенная); арифметики кроме сравнения
count; чтения СОДЕРЖИМОГО текста (язык видит структуру, смысл — честность агента);
отрицания кроме `count: "=0"`; времени; ролей кроме `owner`; сцепления правил (guard над
summary, summary над summary). Черта Тьюринга: сцепление или свои агрегаторы → порядок
вычисления, неподвижные точки, отладчик — язык становится программой, чертёж — кодом.

## 6. Одиннадцать требований раздела 2

| # | Требование | Чем выражено |
|---|---|---|
| 1 | единицы с атрибутами | Unit: поля, метки, связи; вложенность — `part-of` |
| 2 | состояния с логикой | State + явный список Transition в Blueprint |
| 3 | условия на переходе | Guard, атом `bring` (§3) |
| 4 | действия на переходе | Effects: `move` через селектор, и только он (§4) |
| 5 | связи, в т.ч. обязательные | Link-рели в чертеже; обязательность = `have` на `*new*` |
| 6 | сводки по связям | Summary: `have`-селектор + count/all/fraction + lift (§4) |
| 7 | цепочка групп | эмерджентна: `have` на рождениях, тип цели — прошлое звено |
| 8 | группы вне процесса | чертёж без guard/effects; процессность не встроена вовсе |
| 9 | несколько процессов, завершение | несколько чертежей; закрытие досок; чертёж можно запечатать (рождения запрещены, жизнь идёт) |
| 10 | заготовки | Preset: копия чертежа одним действием |
| 11 | видимое ограничение прав | обязательный `enforce`; в тексте — метка у каждой строки |

## 7. Текст правил для агента (генерируется из чертежа)

Закрытый набор атомов ⇒ у каждого атома канонический шаблон-предложение. Объём текста —
O(|переходов| × |атомов|), без свободной логики, которую пришлось бы пересказывать прозой.
Чертёж примера §8а целиком рендерится в ~30 строк — один проход в начале сессии.

```
=== Доска contracts (тип contract) ===
Состояния: draft → review → accepted | rejected (финалы).
Создать contract: только со ссылкой fulfills на ровно один intent в accepted. [СЕРВЕР НЕ ПРОПУСТИТ иначе]
review → accepted:
  - подпись владельца.        [НЕ ТВОЁ РЕШЕНИЕ: сервер пропустит только владельца]
  - записка-обоснование.      [НА ТВОЕЙ ЧЕСТНОСТИ: сервер не проверяет]
Автоматика: когда work уходит в merged, её contract сам перейдёт в delivered.
Сводка ready: доля поставляющих work в финале; поднимается по part-of.
```

## 8. Три рабочих примера (несущие фрагменты чертежей)

**а) заявка → замысел → контракт → работа**
```yaml
intent:
  "*new*" -> draft: {guard: [{have: answers, to: request, in_class: open, count: ">=1", enforce: server}]}
  review -> accepted:
    guard: [{bring: signature, by: owner, enforce: server}, {bring: note, enforce: honor}]
contract:
  "*new*" -> draft: {guard: [{have: fulfills, to: intent, state: accepted, count: "=1", enforce: server}]}
work:
  done -> merged:
    guard:   [{bring: artifact, artifact_kind: commit, enforce: server}]
    effects: [{move: "via fulfills -> delivered"}]
summary contract.ready:
  {over: {have: fulfills, incoming: true, from: work}, measure: fraction in_class done, lift: part-of}
```

**б) вики без процессной роли** — guard-машинерия не всплывает вовсе:
```yaml
page:
  "*new*" -> draft: {}
  draft -> published: {}
  published -> archived: {guard: [{bring: note, enforce: honor}]}  # почему убрали — единственное условие
```

**в) записанные решения; терминал при заведении — норма, не обход:**
```yaml
decision:
  "*new*" -> recorded: {guard: [{bring: note, enforce: honor}]}  # recorded: class done; note = контекст
  # пересмотр = новая единица со связью supersedes, а не «переоткрытие»
```

## 9. Когнитивный бюджет

До первого полезного действия. **Агент-потребитель** (прочитал текст §7, работает): Board, Unit,
State, Transition, Evidence, Link — **6**; Guard ему не термин («переход требует…»), Effect — факт
(«сервер сам переведёт»), Summary — число. **Владелец с Preset:** те же 6, нотация не нужна.
**Автор нового чертежа:** +4 (Blueprint, Guard-нотация, Effect, Summary) = 10, и честно: нотация —
ещё ~10 слов-форм; это порог автора, и он считается. Сложность перенесена на редкого автора.

## 10. Чем платим

- **Порог автора.** Три атома с уточнителями — реальная учёба; четыре именованных поля
  были тупее, но самоочевиднее. Плата за то, что пятое условие не потребует релиза.
- **Отладка = ответ на отказ.** Сервер отвечает непройденными атомами теми же
  каноническими предложениями, что и текст правил, с указанием сторожа:
  ```
  REFUSED review→accepted contract#412:
    - нет подписи владельца [server] — запроси решение у владельца
    - чеклист dor: 2 пункта не отмечены [honor] — отметь или объясни в note
  ```
  Без такого ответа единый язык ХУЖЕ четырёх полей: там имя поля само было подсказкой.
- **Читаемость `any`.** Дизъюнкция ломает линейность текста правил; линтер предупреждает.
- **Каскады effects.** Даже один глагол `move` рождает цепочки правок; статический
  запрет server-guard на цели обязателен и сужает выразительность.
- **Риск монстра.** Каждый атом множит шаблоны текста и ветки сервера. Правило: новый
  атом — после двух независимых процессов, которым он понадобился, и никогда — атом,
  читающий содержимое текста. Черта §5 — часть контракта, не пожелание.
- **Осадок.** Дефиниции чеклистов — отдельный маленький справочник; предъявление едино,
  но сущность-хранилище никуда не делась.

## 11. Где обобщение не окупилось

Effects. Втягивание записей в язык условий — дверь к полноте по Тьюрингу (§4–5); выгодная граница
проходит между «читать» (один язык атомов — guard и сводки) и «писать» (словарь из одного глагола).
