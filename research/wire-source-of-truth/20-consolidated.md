# Сводка: источник истины для определений агентов

Дата: 2026-08-30. Автор: worker-highstakes (Opus 5 (1M context)). Сводит `11-*`…`15-*`, `04-*`, `05-*`, `06-decisions.md`, `prototype/`. Проверки кода перепрогнаны мной, не приняты на слово.

## 1. Четыре вопроса владельца

**(а) Как работают оверлеи.** Сегодня — никак: резолв ВЫБИРАЕТ один документ целиком
(`agent-def-fetch.ts:337-339`), слияния нет ни на одном уровне. Прогнанная в `prototype/`
механика — файловые жесты над каталогом слоя, файл на роль: положить `petbox-<slug>.json` =
ДОБАВИТЬ; тот же файл с частью ключей = ИЗМЕНИТЬ (верхний уровень ключа замещается целиком,
массивы поэлементно НЕ сливаются); `.md` = заместить прозу, `.append.md` = дописать своей секцией
с именем слоя; `{"slug":…,"removed":true,"reason":…}` = УБРАТЬ; `layer.json` `"mode":"replace"` =
ЗАМЕСТИТЬ состав. Порядок тотальный: базис < user < project. Проза не мержится намеренно: `notes`
— блоб (`apply-artifacts.ts:121-123`), вклеенный в середину абзац способен молча противоречить
пронумерованному правилу выше.

**(б) Польза сервера, поимённо.** Генуинно теряется при переходе на файлы ровно одна вещь: живая
правка ролевой прозы без релиза кита и без git у получателя (`$system/default` version=18,
правится регулярно). Не теряются: мерж по ролям, seed-on-create, per-project scope, три
поверхности — операции НАД хранилищем, переносимые на файлы+CLI. Того, что резерв записал в плюс,
нет: авторства правки на сервере НЕТ (`AgentDefinitionView` = Key/Definition/Version/Created/
Updated). Витрина обслуживает сценарий, которого нет: второго человека в инстансе нет.

**(в) Каскад.** Ложится на существующую модель без её переделки: проза и машинные поля уже
разъединены, `rejectModelFields` рекурсивно запрещает привязку на любом уровне слоя,
`diffAgentDefinitions` уже считает дельту. Дорисовать надо два куска: чтение каталога слоёв вместо
одного документа и валидатор каскада (E1 висячая цель, E2 тумбстоун-сирота, E4/E5 конфликт внутри
уровня, W3 слой-ничего-не-меняет) — его нет ни в каком виде. Прототип прогнан мной: трасса, состав
с провенансом по полю, ровно одна E1, **exit 1**.

**(г) HOCON.** Для C#/JVM опыт владельца подтверждается: `withFallback` + `origin()` закрывают и
каскад, и провенанс из коробки. Для TypeScript зрелого аналога НЕТ: единственный кандидат с
заявленным паритетом спеки — 1 звезда, 1224 dl/мес; `defu`/`c12` вообще не имеют операции УБРАТЬ
(nullish при слиянии пропускается). Вывод: свой мерж ~50-100 строк поверх JSON, идиома «null =
убрать» из RFC 7396. Провенанс по полю всё равно считать своим кодом при ЛЮБОМ движке.

## 3. Что оказалось ХУЖЕ, чем думали

1. **Реплик базиса не две, а шесть классов.** Гит `src/common/default-agents.json`; embedded в
   `PetBox.Core`; копия в npm-ките; **третья дисковая — `~/.petbox/wire/default-agents.json`, md5
   совпал с гитом (проверено мной)**; N серверных по проекту; LKG-кэш по проекту. Дисковой
   реплики в домашнем каталоге в отчётах резерва не было вовсе.
2. **Висячие цели не проверяются нигде.** `spawn.allowedRoles` и `escalation.targets` только
   парсятся и рендерятся. Сегодня безвредно ровно потому, что состав неизменяем; с вычитанием
   роли это раздача артефакта, посылающего агента в несуществующий `subagent_type`. Прототип
   ловит это как E1 и падает с exit 1 — на чистом прогоне, не на подложенном дефекте.
3. **Патч и полное определение обязаны иметь РАЗНЫЕ схемы.** `validateAgentDefinition` требует
   `tier` и `requiredCapabilities` у каждой роли (`agent-definition.ts:145-153`, перечитано);
   патч из одного поля этому не удовлетворяет никогда. Нужна вторая функция валидации, полнота
   проверяется на резолве — развилка контракта, а не строчка кода.
4. **Одноразовость сева — заявленный дизайн, а не баг.** «that is the point of seeding it»
   (`DefaultAgentDefinition.cs:24-26`, перечитано); ре-сев отложен сознательно. Спорить надо с
   дизайном. **Плюс C8:** вычитание роли без удаления сирот раздаёт мёртвую роль навсегда.

## 4. Что оказалось ПРОЩЕ

1. Скилы уже названы верно — работы ноль (C5).
2. Расхождение серверных копий пока НУЛЕВОЕ (побайтово равны, кроме тестового `ddf`). Разовая
   миграция стоит дёшево ровно сейчас; окно закрывается первой же правкой канона.
3. `cleanupLegacyArtifact` уже существует и подключён к agent-файлам — безопасное удаление по
   origin-маркеру не надо изобретать, надо переиспользовать.
4. Каскад не требует переделки модели, а его дизайн уже проверяем глазами за минуту: прототип
   прогнан, ожидаемый результат совпал с расписанным руками.

## 5. Развилка, которую должен разрешить владелец

Базис решён: кит и только кит. Открыт ровно один вопрос — **где живут СЛОИ?**

- **A. Файлы.** `.petbox/agents/` в репе + `agents/` в пользовательском конфиг-каталоге.
  *Цена:* мультимашинность руками; надо решить судьбу LKG-кэша и канала «правка прозы без релиза
  кита»; `AGENTS.md:255` переписывается. *Дёшево:* не хватает чтения каталога и валидатора.
- **B. Сервер как хранилище слоёв** (идея владельца). *Цена:* три независимые переделки (C7) плюс
  новая форма кэша слоя. *Польза:* мультимашинность — эмпирически не подтверждена: одна коробка,
  единственное наблюдаемое дублирование — Windows/WSL на ней же.
- **C. Гибрид:** файлы — источник, сервер — необязательная синхронизация пользовательского слоя.
  *Цена:* полярность придётся объявить явно и удерживать — ровно на ней уже сломался `petsonde`.

Клиентский мерж слоёв нужен при ЛЮБОМ из трёх (при B сервер отдаёт слой, мержит всё равно клиент)
— это общий знаменатель, его можно начинать до ответа.
