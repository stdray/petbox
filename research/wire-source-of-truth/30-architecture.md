# Как это будет работать целиком

Дата: 2026-08-30. Собрано после выбора варианта A (D13). Это картина, а не список решений —
решения в `06-decisions.md`, обоснования в `20-consolidated.md`, работы в `60-precards.md`.

## 1. Схема

```
      ИСТОЧНИК ИСТИНЫ                МАШИНА ПОЛЬЗОВАТЕЛЯ                  ХАРНЕССЫ
      ───────────────                ───────────────────                  ────────

   git: src/common/default-agents.json
              │                      ~/<конфиг>/petbox/agents/
              │ npm publish            petbox-reserve.json {removed}
              ▼                        petbox-worker.json  {патч поля}
      npm-пакет petbox-wire                    │
      (БАЗИС внутри пакета)                    │  user-слой
              │                                │
              └────────────┐   ┌───────────────┘
                           ▼   ▼
                    ┌──────────────────┐        <repo>/.petbox/agents/
                    │    РЕЗОЛВЕР      │ ◄────── petbox-review.json  {новая роль}
                    │  базис < user    │         petbox-review.md
                    │      < project   │         petbox-worker.append.md
                    └────────┬─────────┘         layer.json {mode: merge|replace}
                             │                        project-слой
                    ┌────────▼─────────┐
                    │ ВАЛИДАТОР КАСКАДА│  E1 висячая цель · E2 тумбстоун-сирота
                    │  ошибка → exit 1 │  E4/E5 конфликт уровня · W3 пустой слой
                    └────────┬─────────┘
                             │  резолвнутое определение + провенанс по полю
              ┌──────────────┴───────────────┐
              ▼                              ▼
      apply → артефакты ролей          баннер сессии
      .claude/agents/petbox-*.md       (protocol.ts)
      opencode/*, droid/*
```

Сервер в этой схеме **не участвует вовсе**. Он остаётся носителем памяти, канона, задач и
сессий — то есть данных, которых на диске нет и быть не может.

## 2. Что происходит при старте сессии

| сегодня | станет |
|---|---|
| HTTP-запрос определения к серверу — ПЕРВЫЙ шаг каждого старта | чтение трёх каталогов с диска |
| нет сервера → LKG-кэш → встроенный дефолт | нет слоя → просто базис; битый слой → падение с именем файла |
| резолв ВЫБИРАЕТ один документ целиком | резолв МЕРЖИТ три слоя и знает, какой слой дал каждое поле |
| баннер и apply делают два независимых фетча, версии могут разойтись | один резолв, один результат |

Канон памяти по-прежнему тянется с сервера и по-прежнему имеет offline-кэш — это ДРУГОЙ
механизм, его не трогаем (`canon.ts`, `~/.petbox/cache/<project>.canon.md`).

## 3. Раскладка файлов слоя

Один каталог = один слой. Внутри — файл на роль:

| файл | смысл |
|---|---|
| `petbox-<slug>.json` | машинные поля. В базисе — полное определение роли; в слое — ПАТЧ (только меняемые ключи) |
| `petbox-<slug>.md` | проза. Замещает прозу нижнего слоя ЦЕЛИКОМ |
| `petbox-<slug>.append.md` | дополнение к прозе: едет в артефакт отдельной секцией с именем слоя |
| `petbox-<slug>.json` c `{"removed": true, "reason": …}` | тумбстоун — УБРАТЬ роль нижнего слоя |
| `layer.json` | имя слоя и режим: `merge` (по умолчанию) или `replace` — полное переопределение состава |

Проза намеренно НЕ мержится: `notes` вклеивается в артефакт блобом, и абзац, вставленный в
середину, способен молча противоречить пронумерованному правилу выше.

## 4. Технология мержа — и почему это не HOCON

**HOCON забракован как ГОТОВЫЙ ДВИЖОК для TypeScript, а не как идея каскада.** Раскладка выше
из HOCON никогда не следовала — он рассматривался как способ СЛИТЬ слои, а не как формат
хранения. Проверка дала три факта:

1. на C#/JVM опыт владельца воспроизводится: `withFallback` + `origin()` закрывают и каскад, и
   происхождение из коробки;
2. в TypeScript зрелого аналога нет: единственный кандидат с заявленным паритетом спеки — 1
   звезда на GitHub, ~1200 загрузок в месяц;
3. самый популярный TS-загрузчик конфигов (`c12`/`defu`, 92M загрузок в месяц) **не умеет
   операцию УБРАТЬ вообще** — nullish при слиянии молча пропускается.

Вместо движка — **свой мерж, 50-100 строк без зависимостей**, прототип уже прогнан
(`prototype/resolve.mjs`). Правила ровно четыре:

- объект: ключи верхнего уровня замещаются целиком (массивы поэлементно НЕ сливаются);
- `{"removed": true}` — удаление роли (идиома из RFC 7396 «null = убрать»);
- `.md` — замещение, `.append.md` — дописывание;
- порядок тотальный: базис < user < project, приоритет объявлен, не выведен из версий.

Происхождение (какой слой дал поле) считаем сами — этого не даёт бесплатно НИ ОДИН
рассмотренный движок, включая HOCON-порты.

## 5. Что сносим

**В `petbox-wire`:**
- серверный путь получения определения (`agent-def-fetch.ts`: HTTP-фетч, LKG-чтение, LKG-запись);
- LKG-кэш определений `~/.petbox/cache/<project>.agent-def.json` — вместе с механизмом;
- дисковую реплику базиса `~/.petbox/wire/default-agents.json` (базис едет в пакете, копия лишняя).

**НЕ сносим:** `canon.ts` и его кэш; `roles.json` (привязки роль→модель — отдельная система).

**На сервере — сносим ВСЁ (D18), но поэтапно: сначала wire работает без сервера и это подтверждено на живой системе, только потом снос. Поверхностей три:**

| поверхность | что делать |
|---|---|
| `agent-def-fetch` (клиент) | уходит вместе с клиентским путём |
| MCP `agent_def_*` (list/get/upsert/delete) | остаются read-only или удаляются — решить; сегодня ими пользуется агент, чтобы прочитать прозу перед спавном |
| админ-UI `Pages/Admin/ProjectAgentDefs` | становится просмотром реплики, которая больше ни на что не влияет → кандидат на снос |
| `ProjectAgentDefSeeder` | сев теряет смысл: базис едет в ките |
| хранилище `AgentDefinitionService` | остаётся пустым складом; снос — отдельная миграция |

Окно: расхождение серверных копий СЕГОДНЯ нулевое, миграция дёшева ровно сейчас.

## 6. Порядок работ

```
P4 замер реплик ──┐
                  ├─► решение по серверным поверхностям ──► снос хранилища
P6 правка канона ─┘

P1 валидация висячих целей ──► P2 удаление артефактов-сирот ──► P5 клиентский мерж слоёв
   (нужна уже сегодня)          (ПРЕДУСЛОВИЕ вычитания:         (включает снятие LKG)
                                 без неё убранная роль
                                 живёт в харнессе вечно)

P3 централизация пути ~/.petbox ── независима, удешевляет любое будущее решение по каталогу
```

## 7. Что в эту тему НЕ входит

- **Мультимашинность** — системная проблема рабочего места, решается синхронизацией (`restic` и
  подобное), а не механизмом определений (D14).
- **Гигиена конфиг-каталога** — целевой путь, XDG, разделение по типам данных. Это ОТДЕЛЬНАЯ
  тема про `~/.petbox` целиком; каскаду от неё нужен ровно один новый подкаталог `agents/`.
  Никакого разделения `config/secrets/cache/state` определения агентов не требуют.
- **Каскад привязок роль→модель** — другая система (`roles.json` уже имеет профили). Определение
  переносимо, привязка — нет; смешивать нельзя.
