# Ожидаемый результат резолва — написан руками

Дата: 2026-08-30. Это НЕ вывод скрипта: сначала руками расписан ожидаемый результат, потом
`resolve.mjs` сверен с ним. Совпало (см. «Сверка» внизу).

## Что лежит в слоях

| слой | режим | файлы | какую операцию демонстрирует |
|---|---|---|---|
| `base/` | `replace` | 3 роли, `.json` + `.md` | базис: состав целиком |
| `user/` | `overlay` | `petbox-reserve.json` (тумбстоун), `petbox-worker.json` (патч поля), `petbox-orchestrator.md` | УБРАТЬ, ИЗМЕНИТЬ ПОЛЕ, ЗАМЕСТИТЬ ПРОЗУ |
| `project/` | `overlay` | `petbox-review.json`+`.md`, `petbox-orchestrator.json`, `petbox-worker.append.md` | ДОБАВИТЬ роль, ИЗМЕНИТЬ ПОЛЕ, ДОПИСАТЬ прозу |

## Состав после резолва: три роли

`petbox-orchestrator`, `petbox-worker`, `petbox-review`. Роли `reserve` НЕТ — её убрал
тумбстоун в `user/`. Провенанс каждой роли:

- **orchestrator** — `tier`, `requiredCapabilities`, `escalation` из `default`; проза из
  `user:stdray` (замещена целиком); `spawn` из `project:petbox`. Три слоя в одной роли.
- **worker** — всё из `default`, кроме `escalation` (из `user:stdray`, `available:false`) и
  дополнения к прозе (из `project:petbox`, отдельной секцией).
- **review** — целиком из `project:petbox`, новая роль.

## Три вещи, которые здесь важно увидеть глазами

1. **Патч не обязан быть валидным определением.** `user/petbox-worker.json` содержит только
   `slug` + `escalation`. У него нет `tier` и `requiredCapabilities` — и это НОРМА: полноту
   обязан иметь РЕЗОЛЬВ, а не слой. У новой роли (`project/petbox-review.json`) полнота
   обязательна, потому что ниже неё ничего нет — это проверка E3.
2. **Проза замещается, а не мержится.** `user/petbox-orchestrator.md` выбрасывает базисный
   текст целиком; дополнения, накопленные ниже, при замещении СБРАСЫВАЮТСЯ (иначе получишь
   абзац-сироту от слоя, чей текст ты только что выкинул). Дописывание — отдельный файл
   `*.append.md`, оно попадает в артефакт своей секцией `## Дополнение слоя <имя>`, с именем
   слоя в заголовке: читатель видит, кто это сказал.
3. **Резолв ЛОМАЕТСЯ, и это специально.** `user/` убрал `reserve`, поправил
   `worker.escalation`, но забыл `orchestrator.escalation.targets: ["reserve"]`. Ожидаемый
   отчёт валидатора — ровно одна ошибка:
   `E1 orchestrator.escalation.targets → "reserve": роли нет в резолве`, exit-код 1.
   Это главный аргумент за то, что валидация каскада — не украшение: убрать роль без такой
   проверки означает раздать артефакт, который посылает агента в несуществующую роль.
   Починка — одна строка `"escalation": {"available": false}` в `user/petbox-orchestrator.json`.

## Сверка

```
node resolve.mjs                     # трасса + состав + отчёт; exit 1 (ожидаемая E1)
node resolve.mjs --artifact worker   # итоговое тело артефакта, с провенансом в HTML-комментарии
```
Прогнано 2026-08-30: трасса, состав и единственная E1 совпали с расписанным выше. Негативные
проверки (E2 тумбстоун-сирота, E4 `.md`+`.append.md` вместе, E5 имя файла, W3 слой-ничего-не-
меняет) прогонялись на копии прототипа во временном каталоге и сработали; в самом прототипе их
нет намеренно, чтобы «чистый» прогон давал ровно одну ошибку.

## Чем это НЕ является

`resolve.mjs` — игрушка на 90 строк без зависимостей: нет схемы, нет вменяемых сообщений об
ошибках парсинга, нет Windows-путей кроме относительных, нет привязок роль→модель (их в
определении нет и быть не должно). Он существует, чтобы разложенная раскладка была ПРОВЕРЯЕМА
глазами за минуту, а не чтобы из него что-то росло.
