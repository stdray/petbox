## Вопрос 1 — инвариант против разведки

Из 8 форм **инвариантами по природе** (заранее известная цель, ратчет в CI подходит) —
**3: D2, D7, D8**. У всех трёх есть фиксированный, называемый заранее объект («поверхности
существуют», «символ не используется», «атрибут декларирует X») — вопрос задаётся один раз при
написании теста и потом проверяется вечно.

**Разведкой по природе — 5: D1, D3, D4, D5, D6.** Признак: в каждой из них репозиторий закрывает
не форму, а ОДИН заранее известный экземпляр (конкретный тип двери БД, конкретный интерфейс
`IGatedHostedService`, конкретный словарь токенов контейнера, конкретная пара модулей). Когда
экземпляр меняется на другой (не «есть ли поле `ICoreDbFactory`», а «есть ли поле `ILogger`»; не
«кто реализует `IGatedHostedService`», а «кто реализует `IWorkspaceMembershipService`») — готового
ответа нет, и путь к ответу — написать НОВЫЙ файл того же вида (100–400 строк по прецедентам).
Это и есть настоящая граница: 3/8 форм принадлежат CI по природе вопроса, 5/8 — разведке, и то,
что 4 из этих 5 всё же имеют ПО ОДНОМУ живому экземпляру в дереве, не закрывает форму — оно
доказывает, что механизм воспроизводим, но каждый новый вопрос той же формы стоит заново.

## Вопрос 2 — цена девятой формы (на конкретном примере)

Пример из `02-snapshot.md` — D3, вариант из самой постановки: «у каких типов есть поле `ILogger`».
Это не абстрактный, а буквальный пример из формы D3 в снимке, и в дереве он не отвечен нигде
(`DbLayerGuardTests` параметризован по `GuardedFactories`, `ILogger` в этот список не входит).

- **Путь А — существующими средствами.** Грепнуть `ILogger` по `src/**/*.cs` как имя типа поля —
  10–15 минут, но даёт текстовые совпадения (переменные, параметры методов, комментарии,
  `ILogger<T>` дженерик-варианты) без разбора «это правда ПОЛЕ». Честный ответ («поле, а не
  параметр/локальная переменная») без семантики Roslyn получить нельзя — грепом отличить их
  напрямую нельзя. Написать НАДЁЖНЫЙ bespoke guard по образцу `DbLayerGuardTests`
  (рефлексия по `GetFields()` всех типов продуктовых сборок, с guard-the-guard) — по прецеденту
  того же файла (438 строк, обоснование выбора рефлексии против текста на `:31-46`) — реалистично
  **4–8 часов** на первую итерацию с тестами и защитой от ложного нуля, если вопрос захотят
  превратить в вечный ратчет. Если нужен только разовый ответ без ратчета — писать одноразовый
  C#-скрипт с `Assembly.GetTypes().SelectMany(t=>t.GetFields(...))` — **30–60 минут**, без
  гарантии от ложного нуля и без транзитивности.
- **Путь Б — гипотетическим инструментом.** Одна строка запроса поверх уже загруженной модели
  (загрузка ~9,3 с — цифра консолидатора по A, `20-consolidated.md` «п.4» — **не переизмерена мной**)
  + запрос — секунды. НО: этот КОНКРЕТНЫЙ класс вопроса (D3, «поле типа X») ближе всего к тому, что
  уже проверено в исследовании (простой семантический обход членов типа), в отличие от D5
  (call-граф) и D6 (транзитивная связность), которые в сводке консолидатора числятся НЕИЗМЕРЕННЫМИ
  ни у одного из четырёх воркеров (`20-consolidated.md`, «Что осталось непроверенным», п. Ядро).
  Для D3 выигрыш «часы → секунды» правдоподобен уже сейчас; для D5/D6/D1 выигрыш заявлен, но не
  подтверждён замером ни в одном из просмотренных мной файлов.
