## Противоречия с известным
1. **`TenantFromAttribute` на типах: 56, а не 85** (`02-snapshot.md`/README, `q5`). Плюс 36 на
   методах (`q5b`). Сумма 92 ≠ 85 — не арифметическое совпадение с прежним числом. Правдоподобное
   объяснение: 85 — цифра из более раннего/другого прогона (README датирован тем же днём, но модель
   под ним могла отличаться); TenantDeclaration.cs документирует, что MCP-инструменты объявляют
   `[TenantFrom]` то на классе, то на методе — баланс типы/методы плавает при рефакторинге. НЕ
   переисследовал до первопричины — фиксирую расхождение, а не объясняю его.
2. **`ClaimsPrincipal`: 69, а не 68** — на 1 больше снапшота. Похоже на обычный дрейф модели/кода
   за прошедшее время, не на ошибку запроса (тот же `IsUsing`, что в README).
3. **`Scope.Membership` ещё существует В МОДЕЛИ** (`q3`, поле нашлось: `Scope.value__` + 6 членов
   включая `Membership`), хотя в ИСХОДНИКАХ удалено коммитом `ba7c2d42` (13:21:53) — модель снята
   ДО мержа этого коммита в main (`67e97a3e`, 13:25:25). Не противоречие смыслу провала-2 (0
   использований подтверждён), но противоречие «модель = актуальный код».
4. **Runtime-краш, не compile-error**: первая версия `q7` (`f.FieldType.FullName` без null-guard)
   упала с `Object reference not set to an instance of an object` — НЕ `Incomplete query`, а именно
   исключение времени выполнения запроса (код возврата 3, не 2). README про этот класс ошибок не
   предупреждает — новый пункт для памятки языка запросов.
