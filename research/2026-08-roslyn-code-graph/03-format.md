# Обязательная форма файла-инвентаря (читают ВСЕ воркеры)

Твой файл читают: консолидатор (сравнивает с соседними), оркестратор (принимает решение),
владелец (принимает или отвергает вывод). Он должен быть сравним с соседними файлами.

## Жёсткие правила

1. **Лимит 150 строк.** Сырые логи/дампы — отдельным файлом в `measurements/` или `proto/`, ссылкой.
2. **Не пересказывай содержимое файла в чат-ответе.** В ответе — 5–10 строк: вердикт, где файл,
   что сломалось. Контекст оркестратора — дефицитный ресурс.
3. **Каждое утверждение о коде — с источником по легенде** (`01-legend.md`): IL / синтаксис /
   семантика / строки / рантайм-дамп. «Roslyn показал» без уточнения — брак.
4. **Замер — это число с командой, которой оно получено.** «Быстро» / «приемлемо» — брак.
5. **Отрицательный результат обязателен к публикации.** «Не заработало» с текстом ошибки ценнее,
   чем обход молчком.
6. **Не правь файлы соседей.** Только свой.
7. Даты — абсолютные (2026-08-20), не «сегодня».

## Скелет файла

```markdown
# <Область> — <воркер> — 2026-08-20

## Вердикт в одной строке
<работает / не работает / работает с оговоркой X>

## Что проверено эмпирически
| Что | Команда/код | Результат | Источник (легенда) |
|---|---|---|---|

## Замеры
| Операция | Число | Как получено |
|---|---|---|

## Что НЕ проверено и почему
<явный список. Это не признание слабости, это провенанс.>

## Противоречия с известным
<если твои данные расходятся с `02-snapshot.md` или с ожиданием постановки — сюда, явно.>

## Оценка трудозатрат по своей области
<человеко-дни до рабочего состояния, с разбивкой. Диапазон, не точка.>

## Артефакты
<пути к коду/логам>
```

## Про честность

Постановка ждёт возможного ответа «не окупается». Подгонять результат под «получилось» —
худшее, что можно сделать. Если твоя область не взлетела — так и напиши, с доказательством.
