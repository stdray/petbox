# Ландшафт: представление кода для агентов и LLM — воркер H — 2026-08-20

## Вердикт в одной строке

Рынок продаёт две вещи под одной вывеской «индекс для агента» — векторный ранжировщик сниппетов
(Cursor/Windsurf/Augment/DeepWiki) и LSP/Roslyn-обёртку без графа (Serena, CodeMap) — и ни один
разобранный продукт не отдаёт машиночитаемый признак полноты; ближе всех Sourcegraph Deep Search
(список того, что искал) и Devin Agentic MapReduce (тестируемые селекторы вместо «я всё посмотрел»,
но это не про наш кейс); рёбра из рантайма (DI/эндпоинты) везде извлекают статикой — CodeMap прямо
это подтверждает как решение, не оговорку.

## Продукты

### Sourcegraph (Amp / Cody / Deep Search / MCP) — компания Sourcegraph, жив, платный (enterprise + $59/мес)
- **Позиционирование (цитата):** «Deep Search reasons across your entire codebase» — маркетинг.
  Источник рёбер: семантика (SCIP/LSIF) + строки. Язык запросов: есть (`repo:`, `lang:`, `type:symbol`)
- **Сценарии, которые продаёт:** «cross-repository code intelligence: search, navigation, history,
  Deep Search» — док. Deep Search: «detailed source list showing exactly which searches it performed
  and which files it read» — док, ближайшее к провенансу в сегменте. Своя таблица сравнения пишет
  «Exhaustive coverage: every instance across all repos» — маркетинг (вендор сравнивает себя сам)
- **Что честно НЕ обещает / упаковка:** список источников — «что проверено», не «больше негде искать»;
  облачный сервер + MCP-инструмент + IDE-плагин, энтерпрайз

### DeepWiki (Cognition / Devin) — жив, бесплатный для публичных репо
- **Позиционирование (цитата):** «AI documentation you can talk to, for every repo» — статус: маркетинг
- **Источник рёбер:** LLM-генерация поверх синтаксиса — модель читает код и сама пишет связи, не
  компилятор и не рантайм. Язык запросов: нет, естественный язык, диалог с «Ask Devin»
- **Сценарии, которые продаёт:** «architecture-oriented diagrams of how major systems relate» —
  демо (генерит на лету); «page-level summaries link back to source files» — док
- **Что честно НЕ обещает:** точность связей — сгенерированное summary, не гарантированный граф;
  сама компания зовёт это «wiki», не «index». Упаковка: облачный сервис, человек или Ask Devin

### Graphify — независимый OSS (Apache 2.0), активен 2026
- **Позиционирование (цитата):** «no embeddings, just a graph it can trace and cite» — статус: маркетинг
- **Источник рёбер:** синтаксис (tree-sitter WASM, 12-40 языков) — вызовы/импорты/наследование по
  ИМЕНАМ, без резолва перегрузок; сам продукт вводит класс «ambiguous/inferred edges» (см. wiki)
- **Язык запросов:** skill-команда `/graphify`. Сценарии: «what symbols exist, how they connect» —
  маркетинг; «71.5x меньше токенов против чтения сырых файлов» на 52 файлах — замер (базлайн наивный)
- **Что честно НЕ обещает / упаковка:** резолюцию символов (inferred-класс рёбер); skill для Claude
  Code/Cursor/Codex/Gemini CLI, локально

### aider repo map — Paul Gauthier / Aider-AI, живой годами OSS
- **Позиционирование (цитата):** «a function called by 20 others is more valuable context than a
  private helper called once» — статус: док. Источник рёбер: синтаксис (tree-sitter, 130+ языков)
- **Язык запросов:** нет — это РАНЖИРОВАНИЕ: персонализированный PageRank, топ-N в бюджет токенов
- **Сценарии, которые продаёт:** «какие ~20 символов вообще стоит показать модели» — демо (годы
  прод-использования); выше точность правок против наивного включения файлов — замер (бенчмарк aider)
- **Что честно НЕ обещает / упаковка:** полноту — дожатие контекста в бюджет, не поиск ответа;
  библиотека внутри CLI-агента aider, локально

### Cursor / Windsurf / Augment — векторный триплет IDE-агентов, все живы, платные
- **Позиционирование:** Cursor — «Merkle tree sync» инкрементального аплоада чанков (док); Windsurf —
  «M-Query» вместо косинусной близости (маркетинг); Augment — «real-time index... understanding how
  different pieces relate to each other» (маркетинг)
- **Источник рёбер:** строки/векторные эмбеддинги чанков (AST-выровненные у Cursor); Augment
  добавляет граф зависимостей поверх, механизм извлечения рёбер не раскрыт
- **Язык запросов:** нет — семантический поиск по фразе задачи, агент решает, что открыть
- **Сценарии, которые продаёт:** «код, похожий по смыслу на фразу задачи» (уровень 4 из wiki) — док
  у всех трёх; Augment добавляет «indexes commit history... tribal knowledge» — маркетинг
- **Что честно НЕ обещает / упаковка:** резолюцию символов уровня компилятора; встроено в IDE,
  облачный индекс (у Augment есть локальный MCP-режим)

### Cline — открытый VS Code-агент, живой, явно НЕ индексирует
- **Позиционирование (цитата):** «Cline doesn't index your codebase. No RAG, no embeddings, no
  vector databases. This isn't a limitation — it's a deliberate design choice» — статус: маркетинг,
  но с разбором ниже
- **Источник рёбер:** нет индекса вовсе; на лету — AST через синтаксис + чтение файлов по импортам
- **Аргументы против индексации (дословно, статус: маркетинг/блог):** «Code Doesn't Think in
  Chunks» (эмбеддинг рвёт логику) · «Indexes Decay While Code Evolves» (замороженный снимок, код
  дрейфует) · «Security Becomes a Liability» (вторая копия IP = удвоенная поверхность атаки)
- **Что честно НЕ обещает / упаковка:** скорость на большом репо; расширение VS Code, локально

### Claude Code — Anthropic, сознательно без индекса
- **Позиционирование (цитата, Boris Cherny):** «Early versions of Claude Code used RAG + a local
  vector db, but we found pretty quickly that agentic search generally works better» — статус: док
  (интервью, названо явно, не анонимный маркетинг)
- **Источник рёбер:** нет — Glob/Grep/Read по файловой системе в реальном времени
- **Аргументы (статус: демо/анализ третьих лиц):** grep читает файловую систему СЕЙЧАС, индекс,
  собранный в начале сессии, устаревает при первой же правке; удалён embedding pipeline целиком
- **Что честно НЕ обещает / упаковка:** RAG признан сильнее на больших монорепо (док); встроенные
  инструменты агента, ничего не хранится

### Serena — oraios, OSS, живой, LSP-поверх-MCP
- **Позиционирование (цитата):** «the IDE for your agent» — статус: маркетинг
- **Источник рёбер:** семантика через LSP конкретного языка (не Roslyn, любой LSP-сервер) — то же,
  что даёт Go to Definition/Find Usages в IDE
- **Язык запросов:** нет — набор инструментов: `find_symbol`, `find_referencing_symbols`,
  `get_symbols_overview`, `rename_symbol`, `replace_symbol_body`
- **Сценарии, которые продаёт:** «find_referencing_symbols: every call site and usage of a symbol
  across the codebase» — док; точечные правки без переписывания файла целиком — демо (README)
- **Против протухания:** LSP не уведомлялся о внешних правках → отдавал устаревшее; чинили file-system
  polling перед вызовом (issue #634, замер). Ничего похожего на граф; локальный сервер, 30+ языков

### CodeMap — bbajt, OSS (non-commercial), нишевый, C#/.NET — детальный разбор ниже
- «One tool call. Precise answer. No context flood» (маркетинг). Источник рёбер — чисто статика через
  Roslyn, DI/эндпоинты извлечены статическим анализом, не из работающего приложения (док, см. ниже).
  28 MCP-инструментов, не текстовый язык запросов. Локальный MCP-сервер (stdio), резидентный на сессию.
- Прямой конкурент в нашем домене — полный разбор кода, лицензии и D1–D8 в разделе ниже

## CodeMap — build vs adopt (добор по запросу владельца, по коду, не только README)

**1–2. Лицензия и живость.** «CodeMap Non-Commercial License v1.0», копилефт, запрещает продавать/
включать в платный продукт/SaaS, но разрешает прямо: «Use CodeMap internally within a company for
development tooling» — статус: док (LICENSE.MD §7 + FAQ). Наш случай (внутренний инструмент, закрытый
проект) — «Internal Use», разрешено без отдельной лицензии; запрет сработал бы, только если бы PetBox
продавался С CodeMap внутри. Живость (замер): создан 2026-03-06, push 2026-08-07, 20 коммитов, 17
звёзд, 2 контрибьютора, 3 открытых issue (мультирепо/TFS не поддержаны). Не заброшен.

**3. Покрытие D1–D8 (`02-snapshot.md`):** D1 (использования, глубина) — да (`refs.find`+`graph.
callers/callees`). **D2 (носитель атрибута X) — НЕТ**, ни один из 28 инструментов не ищет по атрибуту
в общем виде (см. п.4). D3 (поле типа X) — частично, только через `refs.find` на сам тип X. D4
(implements/extends) — да (`types.hierarchy`). D5 (A без B) — частично, дерево есть, сравнение ручное.
D6 (связность) — да. D7 (поверхности) — частично, эндпоинты есть, фоновые сервисы — нет. **D8
(доказать отсутствие) — НЕТ.**

**4. Наши три провала, по коду.** `const`/enum-в-switch — **не воспроизводится** (замер): `RefKind
Classifier.cs` классифицирует `MemberAccessExpressionSyntax` через `SemanticModel.GetSymbolInfo`
универсально, без спецкейса для `switch` — источник семантика по исходнику, не IL. Атрибут на типе —
**воспроизводится, и хуже NDepend** (замер): в том же файле `if (identifier.Parent is ... or
AttributeSyntax or ...) return null;` — применение атрибута НЕ порождает ребро вообще. Атрибуты видны
только через 4 захардкоженных экстрактора под конкретные имена (`RouteAttribute`, `[Table]` и т.п.) —
произвольный атрибут не найти НИКАК из 28 инструментов.

**5. DI и фабрики (`DiRegistrationExtractor.cs`).** Обходит все вызовы во всех деревьях компиляции,
матчит `Add{Scoped,Singleton,Transient}/TryAdd*` семантически по типу ресивера — регистрация внутри
лямбды ИЛИ внутри extension-метода модуля БУДЕТ найдена (тело метода — узел того же дерева); НЕ будет
найдена, если extension-метод определён в референсной сборке (NuGet) — там нет syntax tree. Фабрики:
тип резолвится только при прямом `new X(...)` в теле лямбды; любая косвенность (`sp =>
sp.GetRequiredService<Factory>().Create()`) даёт буквально `implType = "factory"`. Тот же сентинел
независимо у `roslyn-codelens-mcp` (`"(factory)"`) — структурный потолок статики: 161/629 регистраций
с неизвестной реализацией останутся неизвестными и тут.

**6–7. Поставка и запросы.** MCP по stdio, процесс резидентен на сессию; `IncrementalCompiler.cs`
кэширует `MSBuildWorkspace`+`Solution` между вызовами (док, комментарий в коде). `repo_path` — явный
параметр каждого вызова, не cwd. `GitService.cs`: `RepoId` = SHA-256 от `origin` URL — все git-worktree
с общим origin делят кэш baseline по `RepoId+CommitSha`; без origin — хэш пути, кэш не делится (не баг,
просто нет экономии). Правки worktree видны через `workspace.create`+`index.refresh_overlay` — ровно
то, чего не хватало NDepend («модель только из основного чекаута», `02-snapshot.md` строка 41).
`tests/**` индексируется, если в `.sln` (док, не проверено на PetBox). Языка запросов нет — 28
инструментов, композируемых через `symbol_id`/`workspace_id`.

### Другие Roslyn/.NET игроки — нашёлся более сильный конкурент

`roslyn-codelens-mcp` (MarcelRoozekrans) — **MIT** (не non-commercial), push сегодня, 47 звёзд, 9
контрибьюторов, 30 закрытых issue (замер). 67 инструментов, закрывает две дыры CodeMap:
**`find_attribute_usages`** — реальный общий D2 через `ISymbol.GetAttributes()`, размечен по `target
Kind` (class/interface/.../method/property) — типы и методы разделяются нативно (замер, код);
**`find_reflection_usage`** — то, чего у CodeMap нет вовсе; тесты первоклассные. DI-фабрики — тот же
потолок, сентинел `"(factory)"`.

Прочие живые: **NDepend.MCP.Server** — официальный, на их же IL-движке (те же 3 провала, MCP-обёртка).
**SharpLensMcp** — 67 tools, жив, не разобран глубоко. Мёртвые несмотря на звёзды: `carquiza/RoslynMCP`
(57★, ни коммита после дня создания), `egorpavlikhin/roslyn-mcp` (30★) — звёзды не признак жизни.

**Итог (описательно):** ни CodeMap, ни roslyn-codelens-mcp не берут рёбра из рантайма, оба слепы на
неявные DI-фабрики одинаково; roslyn-codelens-mcp закрывает D2 и рефлексию, CodeMap — нет; ни один не
отдаёт признак полноты (D8); лицензия CodeMap разрешает наш кейс, roslyn-codelens-mcp снимает вопрос
лицензии вовсе (MIT).

## Сценарии, которых НЕТ ни у кого в сегменте

- **Машиночитаемый признак полноты в самом ответе** («искал тут, здесь заведомо не проверял»).
  Sourcegraph Deep Search ближе всех — отдаёт список источников, — но это протокол действий агента,
  не декларация неполноты по схеме. Ни один продукт не публикует «честный ноль» в смысле легенды.
- **Рёбра из живого DI-контейнера/эндпоинт-реестра работающего приложения.** У обоих .NET-примеров
  (CodeMap, roslyn-codelens-mcp) источник — статический разбор РЕГИСТРИРУЮЩЕГО кода, не пробег по
  `IServiceCollection`/`EndpointDataSource` живого процесса; оба одинаково теряют реализацию за
  косвенной фабричной лямбдой. Ближайшее к рантайму — исполнительная трасса (MCGA/DAIRA): видит «что
  вызвалось», не «что зарегистрировано», и это академия, не продукт с ценой.
- **Явный ответ «индекс устарел, вот степень» как поле в ответе агенту.** Бинарно у всех: либо не
  индексируют (Cline, Claude Code), либо чинят молча (Serena — polling), но никто не отдаёт «старше N».

## Противоречия с нашими предположениями

- Рынок раскололся не на «граф vs не граф», а на «векторный ранжировщик vs LSP-обёртка без графа
  вообще» — у большинства крупных игроков это СНИППЕТ-ранжировщик (уровень 4 из wiki), не структура.
  Граф с типизированными рёбрами ближе к CodeMap/roslyn-codelens-mcp (нишевый .NET) и Sourcegraph
  (энтерпрайз), чем к мейнстриму агентских IDE.
- Serena — не слабая версия графа, а осознанная альтернатива: голый LSP без агрегации, и он явно
  достаточен для Find Usages/rename — задачи, для которых мы предполагали граф обязательным.
- Claude Code и Cline не «не успели» сделать индекс — они СРАВНИЛИ RAG с agentic search и RAG
  проиграл на их метриках; прямое опровержение тезиса «индекс всегда лучше grep».
- D2 (носитель атрибута) уже закрыт в нашей же нише сторонним продуктом (`find_attribute_usages`,
  MIT) — это не пустая клетка рынка, как казалось после разбора одного CodeMap.
