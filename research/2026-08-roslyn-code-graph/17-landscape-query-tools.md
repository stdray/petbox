# Ландшафт: инструменты с моделью кода и языком запросов — воркер G — 2026-08-20

## Вердикт в одной строке
Рынок продаёт язык запросов не как «граф ради графа», а чтобы закрыть ОДИН из двух водоразделов —
«найди уязвимость по потоку данных» (CodeQL/Joern) или «инвариант архитектуры как CI-гейт»
(jQAssistant/NDepend/NetArchTest); зрелые продукты решают оба режима ОДНИМ языком через метаданные
запроса, а не двумя инструментами. Neo4j/Cypher встречается только там, где источник — байткод/IL.

## Продукты

### CodeQL — GitHub/Semmle (жив, GHAS платно, движок открыт), 2026
- **Позиционирование (цитата):** «used to analyze code for issues related to security,
  correctness, maintainability, and readability»; alert queries и path queries («describe the
  flow of information between a source and a sink»).
- **Источник рёбер:** семантика — экстрактор трассирует реальную сборку/типовывод, для
  компилируемых языков — фактическую компиляцию.
- **Язык запросов:** QL, датаlog-диалект с ООП-классами. `from ... where ... select ...`,
  для path queries — импорт data-flow библиотеки.
- **Сценарии, которые продаёт:**
  - «найти уязвимость по потоку от источника к стоку» — `док` (path queries, пример в доке)
  - «variant analysis — найти все вариации известного паттерна по кодовой базе» — `маркетинг`
  - «CI-гейт на PR» + «исследовательский запрос вручную» — `док`, разделены тегом `@precision`
    (very-high/high/medium/low): в дефолтные CI-сьюты попадают только высокоточные
- **Что честно НЕ обещает:** сборка БД — 5–60+ минут, блокирующий гейт «на каждый PR» непрактичен;
  типичный паттерн — diff-scoped на PR, полный nightly.
- **Упаковка:** CLI + VS Code extension + сервер (Actions/GHAS). Бесплатно для открытых репо,
  платно в GitHub Advanced Security для приватных.

### Joern / Code Property Graph — joernio (жив, open-source, v2.0.1), коммерческий форк Qwiet AI
- **Позиционирование (цитата):** «The Bug Hunter's Workbench»; «the original implementation of
  the Code Property Graph» — родина самого термина CPG.
- **Источник рёбер:** синтаксис (AST без обязательной компиляции) + собственный dataflow/call-
  graph слой; нерезолвленные вызовы — документированный класс (аналог «ambiguous/inferred»
  из wiki), в отличие от CodeQL.
- **Язык запросов:** Scala DSL поверх CPG.
- **Сценарии, которые продаёт:**
  - «обнаружение уязвимостей в большом коде, включая бинарники/байткод» — `док`
  - «program slicing / taint tracking как контекст для LLM-детектора» — `демо` (Codebadger,
    открытый MCP-сервер поверх Joern) и `замер` академический (LLMxCPG, USENIX Security 2025)
- **Что честно НЕ обещает:** не претендует на разрешение динамического полиморфизма без эвристик.
- **Упаковка:** CLI/REPL, библиотека, MCP-обвязка сторонними. Локально, open-source ядро.

### Glean (Meta) & Kythe (Google) — оба open-source, оба живы с оговоркой
- **Позиционирование:** Glean — «typed, schema-defined facts about source code in a queryable
  database» (engineering.fb.com, 2024-12-19), питает code browsing/search/docgen внутри Meta.
  Kythe — «pluggable, (mostly) language-agnostic ecosystem for building tools that work with
  code» (kythe.io), исторически ядро Google Code Search.
- **Источник рёбер:** семантика — оба через языковые индексаторы (компиляторные фронтенды или
  LSIF/SCIP из существующих LSP-серверов), а не собственный парсер.
- **Язык запросов:** Glean — Angle, датаlog-стиль (анаграмма «Glean» = «рыбачить»). Kythe —
  GraphQL-подобный Kythe query API поверх protobuf-схемы.
- **Сценарии, которые продаёт:** «код-браузинг и code search в монорепо» — `док` (у обоих);
  «межъязыковая схема фактов» — `док`, но стыковка между индексаторами разных языков ручная,
  не автоматическая (см. «Сценарии, которых нет ни у кого»).
- **Что честно НЕ обещает:** Kythe — команда США уволена в апреле 2024, заменена индийской
  поддержкой (Wikipedia) — живо, но не флагманский приоритет Google на 2026.
- **Упаковка:** оба — библиотека + сервер + CLI-индексаторы, self-host, open-source, без SaaS.

### Semgrep & ast-grep — середина: паттерн + щепотка семантики, оба живы
- **Позиционирование (цитата):** Semgrep — «Lightweight static analysis for many languages.
  Find bug variants with patterns that look like source code» (github.com/semgrep/semgrep).
  ast-grep — позиционируется как инструмент для разработки (codemod/lint), не security,
  в противовес Semgrep (ast-grep.github.io/advanced/tool-comparison.html).
- **Источник рёбер:** Semgrep CE — синтаксис (метапеременные, эквивалентности), Semgrep Pro —
  семантика (interprocedural taint для 30+ языков). ast-grep — чистый синтаксис, tree-sitter.
- **Язык запросов:** оба — паттерны кода как запрос (`$X`, `...`), не произвольные предикаты;
  графа и транзитивности нет ни у одного.
- **Сценарии, которые продаёт:**
  - «найти вариант известного бага по паттерну» — `док` (оба)
  - «cross-file/interprocedural taint» — `док`, но только в платном Semgrep Pro
- **Что честно НЕ обещает:** Semgrep CE — taint только в границах одной функции/файла, «will
  miss many true positives». ast-grep — «does not have deep semantic information... only
  operates on the syntactic level».
- **Упаковка:** оба — CLI, CI-шаг (severity ERROR гейтит, WARNING информирует); Semgrep — ещё и
  облачный AppSec Platform.

### jQAssistant — JVM, Neo4j/Cypher, open-source, жив (доки обновлены 2026-02)
- **Позиционирование (цитата):** «a QA tool which allows the definition and validation of
  project specific rules on a structural level», «plugged into the build process».
- **Источник рёбер:** байткод JVM — прямой структурный аналог IL у NDepend (тот же класс
  источника, что и NDepend, но с графовой БД вместо реляционной IL-модели).
- **Язык запросов:** Cypher (Neo4j). Пример правила: `MATCH (t:Test:Method) WHERE NOT
  (t)-[:INVOKES]->(:Assert:Method) RETURN t AS TestWithoutAssertion`.
- **Сценарии, которые продаёт:**
  - «архитектурное правило как часть сборки» — `док`, тег `<constraint>` — красный Maven build
  - «вывести новые факты для отчёта/разведки» — `док`, тег `<concept>` — тот же Cypher, не гейт
- **Что честно НЕ обещает:** не резолвит динамический диспетчинг; внешние типы видны только по
  FQN без деталей членов.
- **Упаковка:** CLI + Maven plugin + встроенный Neo4j сервер для разведки. Локально, бесплатно.

### NetArchTest / ArchUnitNET / ReSharper SSR — .NET без графа
- **Позиционирование:** NetArchTest/ArchUnitNET — архитектурные правила как fluent-API внутри
  unit-теста (ArchUnitNET — .NET-порт Java ArchUnit). ReSharper SSR — «find and, if necessary,
  replace blocks of code that match a specific pattern» по PSI.
- **Источник рёбер:** NetArchTest/ArchUnitNET — чтение скомпилированных сборок (reflection/
  Mono.Cecil), тот же класс, что IL у NDepend, но без метрик и языка запросов. ReSharper SSR —
  семантика (PSI), но фиксированная форма «паттерн → замена», не произвольные предикаты.
- **Язык запросов:** формально нет ни у одного — везде фиксированный DSL/шаблон, не язык с
  агрегациями и транзитивным замыканием.
- **Сценарии, которые продаёт:**
  - «слоистость/зависимости между namespace как unit-тест» — `док`/`демо` (оба .NET-инструмента)
  - «найти+заменить код по структурному шаблону, quick-fix по решению» — `док` (SSR)
- **Что честно НЕ обещает:** NetArchTest — релиз 2021-05-23, по факту заброшен (есть форки).
  SSR — JetBrains сами отмечают «there isn't much documentation».
- **Упаковка:** NetArchTest/ArchUnitNET — библиотека в тестовом проекте, ТОЛЬКО CI-режим, для
  нового вопроса нужен новый C#-метод. SSR — IDE-фича (в Rider не конфигурируется), только
  разведка/quick-fix, в CI не встраивается.

### Sourcetrail — мёртвый ориентир (вендор остановлен 2021-09, форк жив по 2025-12)
- **Позиционирование (было):** визуальный граф-эксплорер для незнакомого кода, семантический
  индекс (clang/java indexer).
- **Источник рёбер:** семантика.
- **Язык запросов:** НЕТ вообще — чистая визуализация без предикатов. Крайняя точка оси.
- **Сценарии, которые продавал:** «понять незнакомую кодовую базу визуально» — `демо` (было).
- **Что честно НЕ обещает:** сама остановка вендором — довод против «граф без запросов» как
  продуктовой стратегии; спрос удержало только сообщество (petermost fork, коммиты по 2025-12).
- **Упаковка:** desktop GUI, локально, было бесплатно.

## Сценарии, которых НЕТ ни у кого в сегменте
1. **Ребро через границу языков/фреймворков по строковому ключу** (TS-клиент → backend route,
   DI-строковый ключ → реализация, `.cshtml` → C#-обработчик). Ни Glean/Kythe (facts per-indexer
   без автостыковки), ни CodeQL/Joern (однопроходные по языку) этого не продают как готовый
   сценарий — согласуется с выводом `02b-prior-art.md` о нашей же нише.
2. **«Доказать отсутствие» как явный продаваемый сценарий с провенансом.** Все инструменты умеют
   вернуть пустой результат, но ни один не продаёт «честный ноль» (`01-legend.md`) как фичу — это
   побочный эффект языка запросов, а не заявленная ценность; и ни один не хранит граф во
   времени — «когда появилось ребро» не запрашивается нигде в сегменте.
3. **Транзитивный граф + автоприменяемый fix в одном инструменте.** У кого есть транзитивность
   (CodeQL, NDepend, jQAssistant, Joern) — нет quick-fix; у кого есть quick-fix (ReSharper SSR) —
   нет транзитивности.

## Противоречия с нашими предположениями
- **`02b-prior-art.md` утверждал: «транзитивность — единственное, что реально требует языка
  запросов».** Рынок это подтверждает лишь частично: у зрелых продуктов язык запросов держит ещё
  и водораздел CI-гейт/разведка ОДНИМ синтаксисом через метаданные (CodeQL `@precision`,
  jQAssistant `<concept>/<constraint>`, NDepend baseline) — то есть язык запросов продаётся не
  только за транзитивность, но и за то, чтобы не держать два разных инструмента для двух режимов.
- **Графовая БД (Neo4j/Cypher) в этом сегменте не привязана к «неисправимости» IL/синтаксиса** —
  jQAssistant существует именно потому, что байткод JVM (аналог нашего IL) даёт содержательную
  структуру для Cypher; там, где источник — компилятор с полным разрешением символов (CodeQL,
  Glean/Kythe), продукты держат СОБСТВЕННЫЙ датаlog-язык (QL, Angle), а не Cypher/Neo4j —
  косвенный аргумент против прямой рекомендации владельца «Neo4j» именно при разрешённой
  Roslyn-семантике, где датаlog-подобный DSL (или LINQ, как у NDepend) ближе к практике рынка.
- **NetArchTest/ArchUnitNET подтверждают** прежний вывод «CI-инвариант — не CLI-запрос»
  буквально: у них нет НИКАКОГО режима разведки, только тест. Это самый чистый пример того
  водораздела, который у нас уже даёт `AuthzDeclarationRatchetTests`.
