## К2. Пример `Scope.Membership` в полевом отчёте больше не пример

**Тип:** chore, одна правка формулировки в wiki `graf-protiv-grep`.

Разделить два утверждения, которые сейчас слиты:
- **Механизм** — «источник IL не выражает член enum в `switch`» — ВЕРЕН и доказан дважды
  независимо от NDepend (проба `System.Reflection.Metadata` воркера A).
- **Пример** — «здесь граф ввёл в заблуждение» — НЕВЕРЕН: владелец проверил и удалил член как
  действительно мёртвый (`ba7c2d42`), то есть ноль привёл к верному решению.

Замена на живой пример: `ProjectAccess.SandboxContainment` — 7 ссылок по семантике (3 метки
`case`), 0 по IL при объявленном поле в метаданных. **Пример обязан идти с SHA** — этот
исчез из кода за те же сутки, что и отчёт.

## К3. Ступень 1: консолидатор трёх источников с провенансом, без языка запросов

**Тип:** feature (если владелец берёт инструмент в план). **Оценка: 4–6 чел-дней.**

Собрать в один CLI то, что УЖЕ написано и работает: `proto/CodeGraphProbe` (семантика),
`proto/ILProbe` (IL), `proto/di/{no-build,full-host}-harness` (рантайм-дамп). Фиксированные
команды под формы D1/D3/D4 — без языка запросов, без индекса, без DuckDB.

Обязательно с первой строки (Р1–Р4, Р6, Р7): источник на каждом ребре; SHA коммита в ответе;
`NotSearched` выводится, а не пишется руками; гейт `CompilationErrors == 0`; метка
`product|test|e2e` на узле; решение ищется вверх от `cwd`; запуск только в своём worktree.

**Что закрывает.** Все три провала NDepend (проверено), дефект worktree, отсутствие тестов
в модели (56,5 % кода), связи через DI. То есть бо́льшую часть того, ради чего NDepend
покупался бы после 3 сентября.

**Приёмка:** `PetBoxClaims` → 67; носители атрибута с разбивкой по уровню и по виду сборки
(96 продуктовых + 2 тестовых зонда РАЗДЕЛЬНО); ответ из двух разных worktree — разный.

## Что НЕ годится в карточки (и почему)

- **«Построить настоящий call-граф»** — ни один воркер его не построил; замер транзитивности
  сделан на СИНТЕТИЧЕСКИХ рёбрах. Это дыра исследования, а не готовая задача: сначала надо
  померить стоимость построения рёбер вызовов на реальном коде.
- **Кросс-языковые рёбра `TS-клиент → MCP-тул → C#-метод`** — единственное место, где отдельная
  модель зарабатывает существование (`02b-prior-art.md`), но постановкой не запрошено и никем
  не оценено.
- **Обнуление записи в дерево через `BaseIntermediateOutputPath`** — техника работает (диф
  пуст), но ломает межпроектные ссылки у 3 из 22 проектов, причина не диагностирована.
  Не карточка, а известный тупик; обходится через Р7 (запуск только в своём дереве).
