# Бесплатные модели провайдера `opencode`: живые, но только для родного клиента

**Итог замера 2026-11-04.** Бесплатные модели работают — из opencode. Из pi не работают, и
**заголовками это не лечится**: запрос, побайтово совпадающий с настоящим запросом opencode,
получает `429 FreeUsageLimitError`. Прежний вывод «дело в квоте аккаунта» **опровергнут**
(более ранний вывод «дело в заголовках» — тоже).

## Что измерено

1. `opencode run --model opencode/deepseek-v4.1-flash-free` → `PONG`, `cost 0` в
   `opencode.db` (`session_message`), трижды подряд, текущий момент. Модель живая.
2. Реплей настоящего запроса opencode (снят MITM-прокси с локальным CA): те же заголовки
   (`authorization` с тем же ключом `oc_sk_05a4…`, `user-agent: opencode/latest/2.2.5/cli`,
   `x-opencode-client: cli`, `x-opencode-project`, `x-opencode-session`,
   `x-opencode-session-id`, `x-session-affinity`, `x-session-id`, `x-opencode-org-id`,
   `b3`, `traceparent`), тот же путь `/inference/openai/v1/chat/completions`, тело **44 283
   байта** байт-в-байт, тот же свежий `ses_…`, созданный opencode секунду назад:

   | клиент реплея | результат |
   |---|---|
   | curl (HTTP/1.1, все заголовки) | 429 `FreeUsageLimitError` |
   | python `http.client` | 429 |
   | node `http2` | сервер h2 не согласует (`Protocol error`) — opencode ходит по HTTP/1.1 |
   | bun `fetch` (тот же TLS-стек, что у opencode) | 429 |
   | **opencode.exe** | **200** |

3. `GET /console/api/v2/config` отдаёт внешнему клиенту 200 и в теле
   `{"providers":{"opencode":{"headers":{"x-opencode-org-id":"wrk_…"}}}}` — оттуда и берётся
   `x-opencode-org-id`. Предварительный вызов config → inference на том же соединении
   результат не меняет (429).

## Что это значит

Различающее звено лежит **ниже HTTP**: одинаковый ключ, путь, сессия, заголовки и тело
проходят только из настоящего бинарника opencode и не проходят из curl/python/node/bun-fetch.
Правдоподобная механика — отпечаток TLS-клиента (JA3/JA4) или стойка, которую шлёт именно
скомпилированный bun-бинарник; прямым замером я это не доказал, но контент запроса как
объяснение исключён.

Практический вывод: **подстановка заголовков бесплатные модели не открывает**, и это не
временная квота — opencode работает с тем же аккаунтом и тем же ключом прямо сейчас.

## Оговорки

- Не проверено: TLS-отпечаток как таковой (нужен mitm с разбором ClientHello либо сравнение
  JA3 скомпилированного bun-бинарника и `bun fetch`). Всё, что исключено — это различие по
  контенту запроса.
- Второй сервер, к которому opencode ходит в том же прогоне, — `api.deepseek.com` (маленькая
  модель `small_model: deepseek/deepseek-flash` из `~/.config/opencode/opencode.json`), к
  бесплатному тарифу отношения не имеет.
- Даже если бы обход удался: это обход ограничения «тариф только из клиента OpenCode». В
  обвязку PetBox такое вносить нельзя.
