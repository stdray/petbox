# Бесплатные модели провайдера `opencode`: заголовками не открываются

Гипотеза: раз шлюз различает клиентов по заголовкам, то бесплатные модели, которые «доступны
только из OpenCode», заработают из pi, если подставить заголовки opencode
(`x-opencode-client`, UA, `x-opencode-session`/`x-opencode-session-id`).

**Не подтвердилась.** Замер 2026-11-04, ключ провайдера `opencode` (Zen, не `opencode-go`),
`POST https://opencode.ai/inference/openai/v1/chat/completions`, `max_tokens: 4`
(`scripts/free-tier-probe.sh`):

| модель (free) | pi-заголовки + pi-сессия | opencode-UA/заголовки + pi-сессия | + реальный `ses_…` |
|---|---|---|---|
| `deepseek-v4.1-flash-free` | 429 `FreeUsageLimitError` | 429 | 429 |
| `glm-5.3-flash-free` | 429 | 429 | 429 |
| `nemotron-3.5-lightning-free` | 429 | 429 | 429 |
| `flint-40b-free` | 429 | 429 | 429 |
| `mimo-v2.6-flash-free` | 429 | 429 | 429 |

Тело ответа одинаково у всех вариантов:

```json
{"type":"error","error":{"type":"FreeUsageLimitError",
 "message":"Free usage limit reached. Free models work in OpenCode (https://opencode.ai); subscribe to OpenCode Go to keep going: https://opencode.ai/go"}}
```

Три довода, что дело не в заголовках:

1. **Ошибка про квоту, не про личность.** `FreeUsageLimitError` / «Free usage limit reached» —
   это лимит аккаунта, а не отказ опознания клиента.
2. **Контроль без заголовка сессии даёт тот же 429, а не `400 MissingSessionID`.** Значит
   проверка бесплатного тарифа выполняется РАНЬШЕ валидации сессии: до заголовков дело не
   доходит.
3. **Тот же набор «pi-заголовков» + тот же pi-`sessionId` на ПЛАТНОЙ модели того же провайдера
   отдаёт `200`** (`deepseek-v4.1-flash`, 31 prompt-токен). То есть и ключ живой, и шлюз
   принимает pi-идентичность — блокируется именно бесплатный тариф.

## Что известно по истории

- Upstream [#9690](https://github.com/earendil-works/pi/issues/9690) (2026-09-17, закрыт
  ботом): тогда отказ был `403 FreeTierError` «free tier can only be used from within
  OpenCode». Автор уже пробовал подставлять заголовки opencode с pi-сессией — тоже `403`;
  проходил только выданный сервером `ses_…` вместе с идентичностью opencode.
- Свои бесплатные модели (по `opencode.db`) opencode реально использовал до 2026-10-08
  (`longcat-2.5-preview-free`, 94 ответа). То есть у аккаунта квота была и кончилась.

## Что решило бы вопрос окончательно

Нужен момент, когда у аккаунта есть остаток бесплатной квоты (новый аккаунт, сброс лимита):
тогда сравнить вариант «pi-заголовки + pi-сессия» против «заголовки opencode + `ses_…`».
Скрипт для этого — `scripts/free-tier-probe.sh`; он ничего не создаёт и тратит единицы токенов.

## Оговорка

Даже если бы это сработало, это обход ограничения «тариф доступен только из клиента OpenCode»,
а не использование документированной возможности: риск по условиям провайдера и по
стабильности (правило проверяется на его стороне и может измениться в любой момент). В
обвязку PetBox такое вносить нельзя.
