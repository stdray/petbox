# ФОРМАТ инвентаря когорт — читать ПЕРВЫМ, до любой работы

Дата: 2026-08-27. Обязателен для всех инвентарей `11-*`, `12-*`, ...
Отклонение от формата = переделка. Если формат мешает — напиши об этом в конце файла,
не меняй молча.

## Задача

Разметить открытые узлы своей доски по двум осям: **класс** (наблюдение / обязательство)
и **когорта** (чем группа рождена). Это разметка, НЕ триаж: статусы не менять, карточки
не заводить, приоритеты не трогать. Доска read-only.

## Определения — единственный источник, не изобретать свои

**НАБЛЮДЕНИЕ.** Утверждение о состоянии системы, которое агент **нашёл бы снова**,
посмотрев туда же. Ключевой тест — воспроизводимость обнаружения, а не важность.
Признаки: «обнаружен дефект X», измерение, находка ревью/аудита, «тест слеп», «доки врут»,
«N из M не покрыто». Решения владельца в теле нет.

**ОБЯЗАТЕЛЬСТВО.** Решение владельца, обещание или зафиксированная договорённость, которую
**никто не перенайдёт**. Признаки: «решено владельцем», связь `links.task_spec` /
`links.idea_spec` на принятую идею или спеку, `supersedes`, начатая работа (`commits`
непустой, статус InProgress/Review), явная договорённость или названная цена решения в теле.

**СМЕШАННОЕ.** Наблюдение, к которому в теле или комментариях уже прилипло решение
владельца. Требует расщепления. Помечать честно — это самый ценный выход разметки.

**Правило разрешения спора:** если сомневаешься между наблюдением и обязательством,
задай один вопрос — *«если это молча закрыть, найдёт ли это агент снова через месяц?»*
Да → наблюдение. Нет → обязательство. Не «важно ли это» — важность тут ни при чём,
важное наблюдение остаётся наблюдением.

## Когорта

Чем группа рождена. По убыванию предпочтения:
1. сессия-родитель, если выводится (тег вида `concern:onboarding-run-0826`, дата в ключе,
   явная ссылка в теле);
2. тема/подсистема (`area:*`);
3. прогон/инцидент, названный в теле.

Когорта — единица массового решения. Цель разметки: чтобы владелец принимал решения
**по когортам**, а не по 190 карточкам.

## Дополнительно пометить

- **ПРОТУХЛО** — утверждение карточки проверяемо и уже неверно (починено, удалено,
  переписано). Проверять по коду/`origin/main`, а не по своему рабочему дереву.
  Не уверен без глубокой проверки — ставь `?` и не трать на это время.
- **ДУБЛЬ** — пара/группа карточек об одном; указать, какая выглядит полнее.
- **ЖДЁТ ВЛАДЕЛЬЦА** — в теле или комментариях есть незакрытый вопрос к владельцу.
  Это самая ценная пометка: такой очереди сейчас не существует как объекта.

## Формат файла

Строго markdown, **не более 200 строк**. Имя файла назначено в задании.

```
# Инвентарь когорт: доска <название>
Дата: 2026-08-27. Агент: <модель, как представился>. Узлов размечено: N из M.

## Сводка
| класс | шт |
|---|---|
| наблюдение | |
| обязательство | |
| смешанное | |

## Когорты
| когорта | шт | класс (преобладающий) | одно решение, которое закрывает всю когорту |
|---|---|---|---|

## Разметка
| key | класс | когорта | пометки | одной строкой: почему такой класс |
|---|---|---|---|---|

## Ждёт владельца
| key | вопрос, как он сформулирован в карточке |
|---|---|

## Что мне мешало / где формат не подошёл
(свободно, коротко; пусто — так и напиши)
```

## Жёсткие ограничения

- **НЕ вставляй содержимое файла в свой ответ в чат.** В чате — только: путь к файлу,
  число размеченных узлов, 3–5 названий когорт, и всё, что противоречит этому формату.
  Контекст оркестратора — дефицитный ресурс, файл уже всё содержит.
- Экономия чтения: сначала `bodyLen:0` по всей доске, тела тянуть только для спорных.
  Не тяни `bodyLen:-1` пачкой «на всякий случай».
- Ничего не писать в PetBox: ни `tasks_upsert`, ни комментариев, ни памяти. Только чтение.
- Отчёт агента — не доказательство. Если утверждаешь ПРОТУХЛО — назови, чем проверил.
